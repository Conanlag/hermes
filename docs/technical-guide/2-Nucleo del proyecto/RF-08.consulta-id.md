# RF-08 — Consulta de trabajo por ID

## Descripción

El requisito RF-08 permite al usuario consultar el estado y los metadatos de un trabajo a partir de su identificador único. Es la operación de lectura puntual de Hermes: dado un `job_id`, el sistema devuelve `Job ID`, `PID`, `Programa`, `Estado`, `Código de salida` y `Argumentos`, o un mensaje útil si el ID no existe.

La implementación sigue la convención de separación de responsabilidades del proyecto. El módulo `job` provee el dato tipado mediante `obtenerJobPorId`, el módulo `status` traduce el estado en ambas direcciones, el módulo `filter` solo presenta por consola y el módulo `validator` (RF-02) protege la entrada antes de consultar. Ningún módulo abre el archivo por un camino propio: todos leen a través del lector central `leerJobs()` de `job.cpp`.

Durante esta feature se corrigió además un crash latente en `filtrarPorStatus` y `filtrarPorPrograma`: imprimían `job["pid"]` y otras claves con `operator[]` const sin verificar existencia, lo que abortaba con Jobs antiguos sin campo `pid`. Ahora toda impresión verifica `contains` con valores por defecto.

---

## Objetivo

La meta técnica exacta de este RF es ofrecer una consulta por ID que devuelva un `Job` tipado sin efectos laterales ni impresión acoplada, reutilizable por cualquier consumidor futuro (CLI, cancelación, red).

> El usuario deberá poder consultar el estado y metadatos de un trabajo por su ID.

Consideraciones actuales:
- Hace: `obtenerJobPorId(jobId, jobOut)` devuelve `true` y rellena el `Job` (incluidos `pid` y `codigoSalida`) o `false` si no existe o el archivo falla, sin imprimir.
- Hace: `statusDesdeTexto` convierte el texto del JSON a `Status` con default seguro `QUEUED` ante basura.
- Hace: `filtrarPorId` presenta `Job ID, PID, Programa, Estado, Código de salida, Argumentos` y reporta `No se encontró el Job ID` si no existe.
- Hace: impresión defensiva en los tres filtros (`N/A`, `0`, `QUEUED` ante claves faltantes).
- NO hace: normalización de estados ni búsqueda difusa; la comparación de `status` y `programa` sigue siendo exacta.
- NO hace: paginación ni formato máquina (JSON de salida); la presentación es texto humano por `cout`.

## Definición de los estados

Este RF usa el `enum class Status` existente en ambas direcciones:

```cpp
enum class Status {
    QUEUED,
    RUNNING,
    SUCCEEDED,
    FAILED,
    CANCELED
};
```

| Estado | Significado en el ciclo de vida | Representación en disco |
| ------ | ------------------------------- | ----------------------- |
| `QUEUED` | Creado, aún no ejecutado (`codigoSalida = -1`, `pid = 0`). También default seguro ante texto desconocido. | `"QUEUED"` |
| `RUNNING` | Proceso en ejecución (`pid` real asignado). | `"RUNNING"` |
| `SUCCEEDED` | Terminó con código `0`. | `"SUCCEEDED"` |
| `FAILED` | Terminó con código distinto de `0` o fallo del supervisor. | `"FAILED"` |
| `CANCELED` | Cancelación solicitada y aplicada. | `"CANCELED"` |

`statusToString` traduce memoria → disco y `statusDesdeTexto` disco → memoria. La consulta por ID siempre presenta mediante `statusToString(job.status)`, nunca el texto crudo.

## Implementación de `.h`

**1. Propósito.**

`job.h` declara el dato y su lectura; `status.h` declara el vocabulario y su traducción. `filter.h` no cambia: sigue prometiendo `filtrarPorId`.

**2. Dependencias.**

```cpp
// job.h
#include <string>
#include <vector>
#include "status.h"
```

`job.h` necesita `status.h` porque `struct Job` contiene un `Status`. `status.h` solo necesita `<string>`.

**3. Estructuras de datos.**

```cpp
struct Job {
    unsigned int job_id;
    int pid;
    string programa;
    vector<string> argumentos;
    Status status;
    int codigoSalida;
};
```

`pid = 0` significa aún sin proceso real; `codigoSalida = -1` significa aún sin resultado.

**4. Prototipos clave.**

```cpp
// status.h
Status statusDesdeTexto(const string& texto);

// job.h
bool obtenerJobPorId(
    unsigned int jobId,
    Job& jobOut
);
```

`statusDesdeTexto` recibe `const string&` y nunca lanza. `obtenerJobPorId` devuelve `bool` con parámetro de salida `Job&`: `true` rellena `jobOut`, `false` indica ausencia o fallo sin imprimir. Se eligió `bool + salida` sobre devolver `Job` directo para no usar excepciones ni valores mágicos, y sobre `std::optional` para no introducir un concepto nuevo al equipo.

## Implementación de `.cpp`

### `statusDesdeTexto` en `status.cpp`

Comparación exacta contra los cinco literales, default `QUEUED`:

```cpp
Status statusDesdeTexto(const string& texto) {
    if (texto == "QUEUED") return Status::QUEUED;
    if (texto == "RUNNING") return Status::RUNNING;
    if (texto == "SUCCEEDED") return Status::SUCCEEDED;
    if (texto == "FAILED") return Status::FAILED;
    if (texto == "CANCELED") return Status::CANCELED;
    return Status::QUEUED;
}
```

Se diseñó sin lanzar porque un estado desconocido en disco no debe abortar la consulta.

### `obtenerJobPorId` en `job.cpp`

Reutiliza el lector central `leerJobs()` (tolera archivo inexistente o corrupto devolviendo arreglo vacío) y recorre con triple chequeo de identidad:

```cpp
json jobs = leerJobs();

for (const auto& item : jobs) {
    if (
        !item.contains("job_id") ||
        !item["job_id"].is_number_unsigned() ||
        item["job_id"] != jobId
    ) {
        continue;
    }
    // ... rellenar jobOut campo por campo ...
    return true;
}

return false;
```

Cada campo se extrae con valores seguros ante ausencia o tipo incorrecto:

```cpp
// pid: acepta entero con o sin signo, default 0
// programa: solo string, default ""
// argumentos: solo elementos string del arreglo
// status: solo string vía statusDesdeTexto, default QUEUED
// codigo_salida: entero con o sin signo, default -1
```

No hay lectura/escritura nueva de archivos, no hay `syscalls` ni memoria manual: toda la E/S pasa por `leerJobs()` y todo el JSON por verificaciones `contains` + `is_*` antes de tocar cada clave.

### `filtrarPorId` adelgazado en `filter.cpp`

Antes mezclaba apertura, parseo, búsqueda e impresión. Ahora delega el dato y solo presenta:

```cpp
void filtrarPorId(unsigned int job_id){
    Job job;

    if (!obtenerJobPorId(job_id, job)) {
        error("No se encontró el Job ID: ", job_id);
        return;
    }

    cout << "Job ID: " << job.job_id << endl;
    cout << "PID: " << job.pid << endl;
    cout << "Programa: " << job.programa << endl;
    cout << "Estado: " << statusToString(job.status) << endl;
    cout << "Codigo de salida: " << job.codigoSalida << endl;

    cout << "Argumentos: ";
    for (const auto& argumento : job.argumentos) {
        cout << argumento << " ";
    }
    cout << endl;
}
```

### Corrección de crash en `filtrarPorStatus` y `filtrarPorPrograma`

Ambas imprimían `job["job_id"]`, `job["programa"]`, `job["pid"]` y `job["status"]` con `operator[]` const sin verificar. Con Jobs antiguos sin `pid`, `nlohmann/json` aborta (`Assertion it != end() failed`). El bloque de impresión ahora verifica cada clave:

```cpp
cout << "PID: ";
if (job.contains("pid")) {
    cout << job["pid"];
} else {
    cout << 0;
}
cout << endl;
```

Mismo patrón para `job_id` (`N/A`), `programa` (`N/A`) y `status` (`QUEUED`). El formato de salida no cambia cuando las claves existen.

## Integración con `main.cpp`, `validator`, `job`, `status` y `filter`

`main.cpp` no cambió en esta feature: la rama `filter id` ya validaba con `validarIdTexto` (RF-02) y llamaba `filtrarPorId(id)`. El flujo ahora es:

1. `main` valida existencia (`argc`) y contenido (`validarIdTexto`).
2. `filtrarPorId` pide el dato a `obtenerJobPorId` (`job`).
3. `obtenerJobPorId` lee con `leerJobs()` y traduce estado con `statusDesdeTexto` (`status`).
4. `filtrarPorId` presenta con `cout` + `statusToString` y `error()` si no existe.

## Integración con RF-01, RF-02, RF-06 y RF-09

Amplía RF-01 (creación y persistencia) con su lectura simétrica. Reutiliza RF-02 (validación de ID) como puerta previa. Usa el vocabulario de RF-06 (`Status`) en ambas direcciones. Adelgaza RF-09 (`filter`) sin cambiar su contrato: `filtrarPorStatus` y `filtrarPorPrograma` conservan firma y formato, solo ganan impresión defensiva.

## Ejemplo de funcionamiento

**1. Consulta existente:**

```bash
./hermes filter id 2
```

**2. Salida en consola:**

```text
Job ID: 2
PID: 882
Programa: sleep
Estado: SUCCEEDED
Codigo de salida: 0
Argumentos: 15
```

**3. Consulta inexistente:**

```bash
./hermes filter id 999
```

```text
No se encontró el Job ID: 999
```

    {
