# RF-21: Protocolo con delimitación y manejo de errores

## Requisito

El protocolo debe delimitar mensajes, identificar errores y tolerar lecturas
o escrituras parciales.

## Cumplimiento

Las solicitudes y respuestas son mensajes JSON separados por un salto de línea
`'\n'`. El servidor acumula todos los bytes recibidos hasta encontrar el
delimitador, mientras que el cliente y el servidor continúan enviando la porción
restante cuando una operación de socket entrega menos bytes de los solicitados.

Los errores de protocolo tienen códigos deterministas y no exponen la excepción
interna de la librería JSON. Las respuestas de error se entregan en el sobre:

```json
{"version":1,"request_id":null,"ok":false,"error":"CODIGO"}
```

Los límites y códigos están definidos en `network_protocol.h` y se aplican tanto
al servidor como al cliente.

## Manejo parcial

- Lectura: `recv()` acumula fragmentos en el buffer de la conexión hasta `\n`.
- Escritura: los bucles utilizan un contador de bytes enviados y reintentan
  cuando el kernel devuelve `EINTR`, `EAGAIN` o `EWOULDBLOCK`.
- Mensaje incompleto: se rechaza sin crear estado ni Job.
- Dos mensajes en un único envío: solo el primer mensaje delimitado se procesa;
  el resto se descarta al cerrar la conexión.
- Respuestas: el cliente valida delimitador, longitud, bytes NUL, JSON, versión
  y coherencia de `request_id`, `ok`, `result` y `error`.

## Evidencia

- TC-031 verifica desconexión, cliente lento y corte durante una respuesta.
- TC-039 verifica errores deterministas para JSON, UTF-8, profundidad,
  parámetros y operaciones inválidas.
- TC-040 verifica la interpretación de sobres de error con `request_id: null`.
- TC-041 verifica el rechazo propio de respuestas mal formadas.
- TC-042 verifica que dos mensajes enviados juntos se traten como una sola
  conexión con solo el primer mensaje procesado.
