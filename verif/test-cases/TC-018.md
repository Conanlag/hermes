# TC-018: Consistencia de transiciones de estado concurrentes

**Requisito cubierto:** RNF-27
**Nivel de prueba:** Integración / concurrencia

## Objetivo

Verificar que las cancelaciones concurrentes no produzcan estados imposibles ni regresiones, que los estados terminales permanezcan terminales y que el resultado persistido corresponda al estado final.

## Precondiciones

- Linux con Bash, Perl `JSON::PP` y Hermes compilado.
- La prueba usa un `HOME` temporal y no modifica los datos del usuario.
- `/proc` debe estar disponible para detener el scheduler aislado al terminar.
- Si se indica una cantidad, debe estar entre 1 y 64, el rango permitido por Hermes.

## Ejecución

Desde la raíz del repositorio:

```bash
make -C src/hermes
bash verif/scripts/TC-018.sh
```

Sin argumentos, el caso crea 5 Jobs `sleep 30` concurrentemente y envía tres solicitudes de cancelación simultáneas por Job. Mientras se procesan, observa los estados persistidos. Comprueba que las transiciones observadas respeten `QUEUED -> RUNNING -> estado terminal` o `QUEUED -> CANCELED`, que ningún estado terminal regrese a otro estado, que todos los Jobs terminen como `CANCELED`, que tengan código de salida no exitoso y tiempo de terminación, y que `jobs.json` siga siendo JSON válido.

Se puede indicar otra cantidad de Jobs:

```bash
bash verif/scripts/TC-018.sh 30
```

El argumento es opcional; sin él se prueban 5 Jobs, igual al límite predeterminado de Hermes. El test configura `trabajos_maximos` a la cantidad elegida únicamente en su `HOME` temporal; no cambia el `config.json` del usuario. Cada ejecución agrega su salida a `verif/results/results_TC-018.md`. El scheduler y los datos temporales se limpian al finalizar.

## Resultado esperado

El script termina con código `0` y muestra:

```text
PASS: 5 Jobs recibieron 15 solicitudes concurrentes; no se observaron regresiones y todos terminaron CANCELED.
```
