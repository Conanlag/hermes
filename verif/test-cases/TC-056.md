# TC-056: El CLI reutiliza la conexión al paginar

**Requisitos cubiertos:** RNF-24
**Métodos de verificación:** Prueba
**Nivel de prueba:** Funcional e integración

#### 1. Fase de Diseño (Planificación)
* **Objetivo:** Verificar que el cliente del CLI mantiene una conexión mientras encadena solicitudes de paginación, y que además tolera un servidor que cierra tras cada respuesta reintentando una sola vez por página.
* **Precondiciones:** Linux o WSL con Bash y Python 3; Hermes compilado; `HOME` temporal aislado; puertos `45862` (servidor real) y `45863` (servidor falso) libres.
* **Entorno y configuración:** `config.json` propio con `trabajos_maximos: 64` y `max_cola: 64`; `network.json` que autoriza a `PC-B` desde `127.0.0.1` con `submit` y `list`. El servidor falso es un proceso Python que acepta tres conexiones y responde una página por conexión.
* **Datos de entrada:** (a) Veintiún `submit` de `true` sobre una sola conexión, seguidos de `hermes red filter 127.0.0.1 programa true`; (b) el mismo comando contra el servidor falso, que devuelve dos Jobs en tres conexiones.
* **Pasos reproducibles:**
  1. Compilar con `make -C src/hermes hermes`.
  2. Ejecutar `bash verif/scripts/TC-056.sh`.
  3. Revisar el código de salida y `verif/results/results_TC-056.md`.
* **Resultado esperado:** (a) El comando imprime 21 líneas `Job ID:` —dos páginas de 20 y 1— sobre la conexión reutilizada. (b) Contra el servidor que cierra, imprime 2 Jobs tras reconectar una vez por página.

#### 2. Fase de Ejecución (Resultados empíricos)
* **Resultado observado:** Ejecución del 2026-11-22 en WSL Ubuntu con código `0`. Se crearon `21` Jobs sobre una sola conexión; `red filter` mostró `21` Jobs en dos páginas sobre la misma conexión. Contra el servidor que cierra cada respuesta, mostró `2` Jobs en `3` conexiones.
* **Artefactos de evidencia:** `verif/scripts/TC-056.sh`; `verif/results/results_TC-056.md`.
