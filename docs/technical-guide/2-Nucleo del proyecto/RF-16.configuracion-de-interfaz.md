# RF-16: Configuración de datos, concurrencia y escucha

Hermes lee la configuración de `~/.config/hermes/config.json` (o de
`$XDG_CONFIG_HOME/hermes/config.json` si XDG_CONFIG_HOME es una ruta absoluta).
`make`, `make install` y el arranque del ejecutable crean el directorio,
`config.json` y `config.lock` si faltan mediante la inicialización C++.
Los archivos existentes se conservan. `hermes configmax` crea o actualiza la configuración de forma
atómica, conservando las otras claves.

Ejemplo:

```json
{
    "directorio_datos": "/home/usuario/.local/share/hermes/data",
    "trabajos_maximos": 5,
    "max_cola": 0,
    "interfaz": "127.0.0.1",
    "puerto": 45820
}
```

- `directorio_datos`: ruta absoluta, sin expansión de `~` ni variables de entorno.
  Por defecto: `$HOME/.local/share/hermes/data`.
- `trabajos_maximos`: concurrencia del scheduler entre 1 y 64; valor inicial 5.
- `max_cola`: cupos de espera entre 0 y 256; valor inicial 0.
- `interfaz`: dirección IPv4 literal de escucha; valor inicial `127.0.0.1`.
- `puerto`: entero entre 1 y 65535; valor inicial 45820, según ADR-015.

Las claves son opcionales. Los campos de red o ruta inválidos usan sus valores
predeterminados y generan advertencias. Los valores enteros de concurrencia y
cola se ajustan a sus límites históricos. Las actualizaciones mediante
`CambiosConfiguracion` rechazan valores inválidos antes de escribir cualquier
clave. Esta API permite actualizar también directorio, interfaz y puerto.

## Compatibilidad y cambio de directorio

Si no existe el archivo nuevo y existe
`~/.local/share/hermes/data/config.json`, la inicialización copia sus valores al archivo nuevo y conserva el antiguo
como respaldo. Ejecutar la actualización con Hermes detenido.
El archivo nuevo tiene prioridad; no se mezclan ambos archivos.

Antes de cambiar `directorio_datos`, detener el scheduler y los trabajos activos.
La ruta queda fijada durante cada proceso; reiniciar Hermes para aplicar el
cambio. Hermes crea el directorio y los archivos de almacenamiento que falten,
pero no mueve ni elimina los trabajos existentes: para conservarlos en otra
ruta, copiar el almacenamiento con Hermes detenido. La configuración y su
`config.lock` permanecen juntos, fuera del directorio personalizado.

Esta entrega prepara la configuración de escucha; el servidor TCP y sus reglas
de acceso corresponden a requisitos posteriores.

## Verificación

Desde la raíz del repositorio:

```sh
make -C src/hermes
bash src/hermes/tests/rf16.sh
```

Las pruebas usan directorios temporales y cubren compatibilidad antigua, rutas
personalizadas, conservación de campos, valores inválidos, enteros grandes y
JSON corrupto.

No hay un comando init ni scripts de preparación. `make` compila y ejecuta
el arranque normal (`./hermes` sin argumentos), que crea solo los archivos
faltantes y prepara los enlaces `data` y `config` en la copia de desarrollo.
No inicia el scheduler ni el servidor de red. `make install` hace lo mismo
antes de copiar el ejecutable. El arranque también funciona si se ejecuta el
binario directamente, sin pasar por make.

Los enlaces se mantienen versionados en Git. Sus destinos son literales:
Git no expande HOME al clonar. Hermes actualiza únicamente enlaces simbólicos
en la copia de desarrollo al arrancar sin argumentos, respetando XDG_CONFIG_HOME
y directorio_datos. Si encuentra un archivo o directorio real en su lugar,
lo conserva y muestra un error. El binario instalado no crea enlaces en su
carpeta de instalación. Una ruta adaptada a otro usuario puede aparecer como
modificación local del enlace en Git.
