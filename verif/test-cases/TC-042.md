# TC-042: Dos mensajes en un envío se resuelven como uno

**Requisitos cubiertos:** RNF-14
**Métodos de verificación:** Prueba
**Nivel de prueba:** Funcional y robustez

#### 1. Fase de Diseño (Planificación)
* **Objetivo:** Verificar que el servidor procesa estrictamente un mensaje por conexión: si el cliente envía dos sobres en un solo `write`, solo el primero se interpreta y el segundo se descarta sin crear estado.
* **Precondiciones:** Linux o WSL con Bash y Python 3; Hermes compilado; `HOME` temporal aislado; puerto `45853` libre.
* **Entorno y configuración:** `config.json` propio con `puerto: 45853`; `network.json` que autoriza a `PC-B` desde `127.0.0.1` con `submit` habilitado; servidor lanzado por el script.
* **Datos de entrada:** Un único `sendall` con dos sobres `submit` completos y consecutivos (`tc042-primero` y `tc042-segundo`), cada uno terminado en salto de línea.
* **Pasos reproducibles:**
  1. Compilar con `make -C src/hermes hermes`.
  2. Ejecutar `bash verif/scripts/TC-042.sh`.
  3. Revisar el código de salida y `verif/results/results_TC-042.md`.
* **Resultado esperado:** La respuesta corresponde a `tc042-primero` con `ok: true`. `jobs.json` contiene exactamente un Job y ninguna referencia a `tc042-segundo`. El `ping` posterior responde correctamente.

#### 2. Fase de Ejecución (Resultados empíricos)
* **Resultado observado:** Ejecución del 2026-11-19 en WSL Ubuntu con código `0`. La respuesta fue `{"ok": true, "request_id": "tc042-primero", ...}` con `job_id: 1`; `jobs.json` contenía `1` Job y ninguna mención a `tc042-segundo`; el `ping` posterior respondió correctamente.
* **Artefactos de evidencia:** `verif/scripts/TC-042.sh`; `verif/results/results_TC-042.md`.
