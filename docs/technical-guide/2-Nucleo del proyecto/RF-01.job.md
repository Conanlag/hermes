
# Gestión de Jobs — RF-01

## 1. Objetivo

El módulo `job` implementa la funcionalidad correspondiente al **RF-01** de Hermes:

> El sistema deberá aceptar el envío de un comando o programa con sus argumentos y devolver un identificador único de trabajo.

En esta etapa, Hermes **no ejecuta el programa recibido**. El programa y sus argumentos se almacenan dentro de una estructura `Job` y se persisten en un archivo JSON.

Cada nuevo Job recibe un identificador único generado a partir de los Jobs previamente almacenados.

---

# 2. Estructura del módulo

La implementación utiliza la siguiente estructura:

```text
hermes/
│
├── include/
│   └── nlohmann/
│       └── json.hpp
│
├── src/
│   └── hermes/
│       ├── job.h
│       ├── job.cpp
│       └── main.cpp
│
├── data/
│   └── jobs.json
│
└── Makefile
```

### Componentes

| Archivo / directorio        | Responsabilidad                                                  |
| --------------------------- | ---------------------------------------------------------------- |
| `job.h`                     | Define la estructura `Job` y declara la función `crearJob()`     |

| `Makefile`                  | Configura y ejecuta la compilación del proyecto                  |
| `main.cpp`                  | Recibe los argumentos del comando y solicita la creación del Job |

# 3. Dependencia nlohmann/json

Hermes utiliza la biblioteca **nlohmann/json v3.12.0** para leer y escribir la información de los Jobs en formato JSON.

La biblioteca es de tipo **header-only**, por lo que no requiere enlazar una biblioteca adicional durante la compilación.

El archivo utilizado es:

```text
include/nlohmann/json.hpp
```

La dependencia se encuentra directamente dentro del repositorio de Hermes para evitar depender de una instalación global en el sistema.

Por lo tanto, no es necesario instalarla mediante el administrador de paquetes del sistema:

```bash
sudo apt install nlohmann-json3-dev
```

La compilación utiliza directamente la versión almacenada en el proyecto.

## 3.1 Inclusión en C++

Los archivos que utilizan la biblioteca pueden incluirla mediante:

```cpp
#include <nlohmann/json.hpp>

using json = nlohmann::json;
```

## 3.2 Integración con Makefile

El `Makefile` agrega el directorio `include` como ruta de búsqueda para los archivos de cabecera:

```make
CXXFLAGS = -Wall -Wextra -std=c++17 -Iinclude
```

La opción:

```text
-Iinclude
```

permite que el compilador encuentre:

```text
include/nlohmann/json.hpp
```

cuando el código utiliza:

```cpp
#include <nlohmann/json.hpp>
```

No es necesario utilizar:

```text
-ljson
```

debido a que `nlohmann/json` es una biblioteca *header-only*.

# 4. `job.h`

## 4.1 Propósito

El archivo `job.h` contiene la definición de la estructura que representa un trabajo dentro de Hermes.

También declara la función encargada de crear un nuevo Job.

## 4.2 Dependencias

```cpp
#include <string>
#include <vector>
```

Se utilizan:

* `std::string` para almacenar el nombre del programa.
* `std::vector<std::string>` para almacenar sus argumentos.

## 4.3 Estructura `Job`

```cpp
struct Job {
    unsigned int id;
    string programa;
    vector<string> argumentos;
};
```

La estructura contiene actualmente tres elementos.

### `id`

```cpp
unsigned int id;
```

Identificador del trabajo.

Este valor permite distinguir un Job de otro.

El identificador se genera consultando los Jobs existentes en `data/jobs.json`.

### `programa`

```cpp
string programa;
```

Contiene el nombre o comando recibido por Hermes.

Ejemplo:

```text
ls
```

### `argumentos`

```cpp
vector<string> argumentos;
```

Contiene los argumentos asociados al programa.

Por ejemplo, para:

```bash
hermes job ls -la /tmp
```

se almacena:

```text
programa = "ls"

argumentos:
    "-la"
    "/tmp"
```

## 4.4 Función `crearJob()`

La función se declara como:

```cpp
Job crearJob(
    const string& programa,
    const vector<string>& argumentos
);
```

Recibe:

1. El programa.
2. Los argumentos del programa.

Y devuelve:

```cpp
Job
```

con un identificador asignado.

Además de crear el objeto en memoria, la implementación actual persiste el nuevo Job en `data/jobs.json`.

---

# 5. `job.cpp`

## 5.1 Propósito

`job.cpp` contiene la implementación de `crearJob()`.

Su responsabilidad actual es:

1. Leer los Jobs existentes desde `data/jobs.json`.
2. Determinar el siguiente `job_id`.
3. Crear un `Job`.
4. Asignar el ID.
5. Guardar el programa.
6. Guardar los argumentos.
7. Agregar el nuevo Job al arreglo JSON.
8. Persistir nuevamente la información en `data/jobs.json`.
9. Devolver el Job.

El módulo **no ejecuta el programa recibido**.

## 5.2 Archivo JSON

La persistencia se realiza mediante:

```cpp
const string archivoJobs = "data/jobs.json";
```

Este archivo contiene un arreglo JSON con los Jobs creados.

Ejemplo:

```json
[
    {
        "job_id": 1,
        "programa": "ls",
        "argumentos": [
            "-la",
            "/tmp"
        ]
    },
    {
        "job_id": 2,
        "programa": "pwd",
        "argumentos": []
    }
]
```

Cada elemento del arreglo representa un Job.

---

# 6. Lectura de los Jobs existentes

Antes de crear un nuevo Job, `crearJob()` intenta abrir:

```text
data/jobs.json
```

mediante:

```cpp
ifstream archivoLectura(archivoJobs);
```

Si el archivo existe, su contenido se carga en un objeto JSON:

```cpp
json jobs = json::array();

if (archivoLectura.is_open()) {
    try {
        archivoLectura >> jobs;
    } catch (const json::parse_error&) {
        jobs = json::array();
    }

    archivoLectura.close();
}
```

El contenido se representa mediante:

```cpp
json jobs;
```

Inicialmente se establece como un arreglo vacío:

```cpp
json::array()
```

Esto permite que Hermes pueda comenzar a crear Jobs aunque todavía no exista información almacenada.

---

# 7. Generación del `job_id`

El siguiente identificador se obtiene recorriendo los Jobs existentes:

```cpp
unsigned int siguienteId = 1;

for (const auto& job : jobs) {
    if (job.contains("job_id") &&
        job["job_id"].is_number_unsigned()) {

        unsigned int id = job["job_id"];

        if (id >= siguienteId) {
            siguienteId = id + 1;
        }
    }
}
```

El valor inicial es:

```text
1
```

Si no existen Jobs, el primer Job recibe:

```text
job_id = 1
```

Si el archivo contiene:

```json
[
    {
        "job_id": 1,
        "programa": "ls",
        "argumentos": []
    },
    {
        "job_id": 2,
        "programa": "pwd",
        "argumentos": []
    }
]
```

el siguiente identificador será:

```text
3
```

## 7.1 Búsqueda del ID máximo

El algoritmo no depende únicamente de la cantidad de elementos del arreglo.

Por ejemplo, si el archivo contiene:

```json
[
    {
        "job_id": 1,
        "programa": "ls",
        "argumentos": []
    },
    {
        "job_id": 5,
        "programa": "pwd",
        "argumentos": []
    }
]
```

el siguiente identificador será:

```text
6
```

Esto se debe a que `crearJob()` busca el identificador más alto almacenado y utiliza el siguiente valor.

---

# 8. Creación del Job

Una vez obtenido el siguiente identificador, se crea el objeto:

```cpp
Job job;
```

Posteriormente se asignan sus datos:

```cpp
job.id = siguienteId;
job.programa = programa;
job.argumentos = argumentos;
```

Por ejemplo:

```bash
hermes job ls -la /tmp
```

produce conceptualmente:

```text
Job
├── id: 1
├── programa: "ls"
└── argumentos:
    ├── "-la"
    └── "/tmp"
```

---

# 9. Conversión del Job a JSON

Después de crear el `Job`, se genera su representación JSON:

```cpp
json nuevoJob;

nuevoJob["job_id"] = job.id;
nuevoJob["programa"] = job.programa;
nuevoJob["argumentos"] = job.argumentos;
```

El resultado es conceptualmente:

```json
{
    "job_id": 1,
    "programa": "ls",
    "argumentos": [
        "-la",
        "/tmp"
    ]
}
```

Este objeto posteriormente se agrega al arreglo de Jobs:

```cpp
jobs.push_back(nuevoJob);
```

---

# 10. Persistencia del Job

Después de agregar el nuevo Job al arreglo, se abre el archivo para escritura:

```cpp
ofstream archivoEscritura(archivoJobs);
```

El arreglo completo se escribe nuevamente en el archivo:

```cpp
archivoEscritura << jobs.dump(4);
```

El parámetro:

```text
4
```

indica el nivel de indentación utilizado para generar un JSON legible.

Por ejemplo:

```json
[
    {
        "job_id": 1,
        "programa": "ls",
        "argumentos": [
            "-la",
            "/tmp"
        ]
    }
]
```

---

# 11. Persistencia de los identificadores

A diferencia de la implementación anterior, Hermes ya no utiliza:

```text
data/job_id
```

para almacenar el siguiente identificador.

Anteriormente el flujo era:

```text
data/job_id
    │
    └── siguiente ID
```

La implementación actual obtiene el identificador directamente de:

```text
data/jobs.json
```

Por ejemplo:

```json
[
    {
        "job_id": 1,
        "programa": "ls",
        "argumentos": []
    },
    {
        "job_id": 2,
        "programa": "pwd",
        "argumentos": []
    }
]
```

El siguiente Job recibirá:

```text
job_id = 3
```

Esto permite que el archivo JSON funcione tanto como almacenamiento de los Jobs como fuente para determinar el siguiente identificador.

# 12. Directorio `data`

## 12.1 Propósito

El directorio `data/` contiene información persistente utilizada por Hermes.

Actualmente contiene:

```text
data/
└── jobs.json
```

## 12.2 Archivo `jobs.json`

`jobs.json` almacena los Jobs creados por Hermes.

Cada elemento del arreglo contiene:

```text
job_id
programa
argumentos
```

Ejemplo:

```json
[
    {
        "job_id": 1,
        "programa": "ls",
        "argumentos": [
            "-la"
        ]
    },
    {
        "job_id": 2,
        "programa": "echo",
        "argumentos": [
            "Hola"
        ]
    }
]
```

## 12.3 Persistencia

La utilización de `jobs.json` permite conservar los Jobs después de que termina el proceso de Hermes.

Por ejemplo:

```bash
hermes job ls
```

puede producir:

```text
Job ID: 1
```

Posteriormente:

```bash
hermes job pwd
```

produce:

```text
Job ID: 2
```

Aunque cada comando corresponde a una nueva ejecución del programa `hermes`, la información de los Jobs permanece almacenada en:

```text
data/jobs.json
```

---

Ahora el sistema puede recuperar:

* Identificador del Job.
* Programa solicitado.
* Argumentos utilizados.

Esta modificación establece una base para futuras funcionalidades de Hermes, como consulta de Jobs, seguimiento de estados y recuperación de información persistente.

---

# 15. Consideraciones actuales

Esta implementación corresponde a la etapa inicial de persistencia de RF-01.

Actualmente:

* Los Jobs se almacenan en `data/jobs.json`.
* Los identificadores se obtienen a partir de los Jobs existentes.
* Los programas no se ejecutan.
* Los argumentos únicamente se almacenan.
* No existe todavía un estado de ejecución del Job.
* No se almacenan `stdout` ni `stderr`.
* No existe persistencia mediante SQLite.
* No existe todavía ejecución concurrente.
* No existe comunicación remota.
