# TC-041: El cliente rechaza respuestas mal formadas con diagnóstico propio

**Requisitos cubiertos:** RNF-14, RNF-32
**Métodos de verificación:** Prueba
**Nivel de prueba:** Robustez e integración

#### 1. Fase de Diseño (Planificación)
* **Objetivo:** Verificar que el cliente valida longitud, delimitador, bytes nulos, versión y coherencia del sobre en toda respuesta entrante, y falla con un mensaje claro en lugar de una excepción de la librería.
* **Precondiciones:** Linux o WSL con Bash y Python 3; Hermes compilado; `HOME` temporal con `config.json` que apunta al puerto de la prueba; puerto `45852` libre.
* **Entorno y configuración:** Servidor falso en Python que responde a cada conexión con un defecto distinto, tomando el `request_id` de la petición real para que solo el defecto bajo prueba invalide la respuesta. El cliente se invoca como `hermes red job 127.0.0.1 true`.
* **Datos de entrada:** Siete respuestas: sin delimitador de salto de línea, de 262200 bytes sin delimitador, con byte nulo embebido, con `version: 2`, con `ok: true` sin `result`, con `ok: false` sin `error`, y JSON no parseable.
* **Pasos reproducibles:**
  1. Compilar con `make -C src/hermes hermes`.
  2. Ejecutar `bash verif/scripts/TC-041.sh`.
  3. Revisar el código de salida y `verif/results/results_TC-041.md`.
* **Resultado esperado:** Las siete invocaciones terminan con código distinto de cero y un diagnóstico propio: `cerró o rechazó la conexión`, `Respuesta demasiado grande`, `contiene un byte nulo`, `version ausente o distinta de 1`, `result ausente o no es objeto`, `error ausente o vacío` y `JSON mal formado`. Ninguna salida contiene `json.exception`, `type_error` ni `[json`.

#### 2. Fase de Ejecución (Resultados empíricos)
* **Resultado observado:** Ejecución del 2026-11-19 en WSL Ubuntu con código `0`. Las siete respuestas fueron rechazadas con el diagnóstico esperado y código de salida `1`. La verificación de salida no encontró `json.exception`, `type_error` ni `[json`. La primera corrida del caso detectó un defecto real: el cliente propagaba el texto de `nlohmann::json` en la respuesta no parseable; se corrigió el mensaje antes de registrar el PASS.
* **Artefactos de evidencia:** `verif/scripts/TC-041.sh`; `verif/results/results_TC-041.md`.
* **Estado:** PASS
