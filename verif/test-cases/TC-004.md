### TC-004: Consultar y listar
**Requisitos cubiertos:** RF-08, RF-09
**Nivel de prueba:** Sistema

#### 1. Fase de Diseño (Planificación)
* **Objetivo:** Validar la consulta puntual por ID (estado y metadatos completos, incluidos tiempos y código de salida) y el listado con filtros básicos por estado, programa e ID, con mensajes útiles ante IDs inexistentes y filtros sin resultados.
* **Precondiciones:** Repositorio clonado limpio; `src/hermes` compilado con `make clean && make` sin errores; `data/jobs.json` respaldado; al menos un trabajo en cada estado representativo (`SUCCEEDED`, `FAILED`, `CANCELED`) creado con `./hermes job true`, `./hermes job false` y `./hermes job sleep 30` + `./hermes cancel`.
* **Entorno y configuración:** Linux (WSL), compilador GCC (g++, `-Wall -Wextra -std=c++17 -Iinclude`), entorno controlado, clon limpio, límite de concurrencia definido en config.json.
* **Datos de entrada:** IDs reales anotados (`S` exitoso, `F` fallido, `C` cancelado, `999999` inexistente); filtros `./hermes filter id <N>`, `./hermes filter status <ESTADO>`, `./hermes filter programa <nombre>`.
* **Pasos reproducibles:**
  1. Compilar: `cd src/hermes && make clean && make`.
  2. Consulta puntual válida: `./hermes filter id S` y comprobar `Job ID, PID, Programa, Estado, Codigo de salida, Recepcion, Inicio, Terminacion, Argumentos` con código `0`.
  3. Consulta inexistente: `./hermes filter id 999999` y comprobar `No se encontró el Job ID` con código `1` y sin modificar el JSON.
  4. Listado por estado: `./hermes filter status SUCCEEDED`, `./hermes filter status FAILED` y `./hermes filter status CANCELED`; comprobar que cada bloque contiene solo trabajos de ese estado.
  5. Listado por programa: `./hermes filter programa sleep` (o el programa usado) y comprobar que todos los bloques corresponden a ese programa.
  6. Filtro sin resultados: `./hermes filter status CANCELED` en un clon sin cancelados (o estado sin representantes) y comprobar mensaje útil con código `1`.
* **Resultado esperado:** Pasos 2, 4 y 5 muestran datos completos y coherentes con `jobs.json` (tiempos con formato `%Y-%m-%d %H:%M:%S`); pasos 3 y 6 rechazan con mensaje útil, código `1` y cero efectos laterales en disco.
