# TC-004: Consultar, listar y medir rendimiento de consultas

**Requisitos cubiertos:** RF-08, RF-09, RNF-05
**Métodos de verificación:** Según la matriz de trazabilidad
**Nivel de prueba:** Sistema

#### 1. Fase de Diseño (Planificación)
* **Objetivo:** Validar la consulta de un Job por ID, los filtros por estado y programa, los mensajes para IDs inexistentes y filtros sin resultados, y que la consulta por programa responda en menos de `1.0 s` con al menos 100 Jobs `echo` persistidos.
* **Precondiciones:** Linux (incluido WSL) con Bash, `grep`, `sed`, `awk`, Perl y `JSON::PP`; Hermes compilado con GCC o Clang; acceso a `/proc` para limpiar el scheduler de prueba. Se requiere un clon del repositorio y no se depende del historial previo del usuario.
* **Entorno y configuración:** Entorno controlado. El script compila Hermes con `make clean && make`, crea un `HOME` temporal aislado y configura `trabajos_maximos` a 64 antes de iniciar el scheduler. No modifica la configuración ni el historial reales del usuario; no requiere LAN ni VPN.
* **Datos de entrada:** Jobs de prueba `true`, `false`, `sleep 30`, 100 Jobs `echo hola`, ID inexistente `999999` y programa inexistente `inventado`. La medición utiliza `./hermes filter programa echo` y cuenta las entradas `Job ID:` devueltas.
* **Pasos reproducibles:**
  1. Desde la raíz del repositorio, ejecutar `bash verif/scripts/TC-004.sh`. El script compila Hermes y aísla los datos mediante un `HOME` temporal.
  2. Confirmar las consultas puntuales y listados por ID, estado y programa, así como los mensajes para el ID inexistente y el filtro sin coincidencias.
  3. El script crea 100 Jobs `echo hola`, espera a que cada uno termine en `SUCCEEDED`, ejecuta `time ./hermes filter programa echo` y valida que se devuelvan al menos 100 Jobs en menos de `1.0 s`.
  4. Revisar la salida, el código de terminación y `verif/results/tc004.log`.
* **Resultado esperado:** El script termina con código `0` y muestra `[PASS] TC-004`. Las consultas por ID y filtros deben devolver datos coherentes, y las consultas vacías deben mostrar un mensaje informativo. Para RNF-05, la consulta de `programa echo` debe listar al menos 100 Jobs y tardar estrictamente menos de `1.0 s`; la prueba falla si no alcanza la cantidad mínima o si excede el umbral.
