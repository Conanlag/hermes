# TC-053: Un mensaje excesivo cierra y no procesa el sobre encadenado

**Requisitos cubiertos:** RNF-24
**Métodos de verificación:** Prueba
**Nivel de prueba:** Robustez

#### 1. Fase de Diseño (Planificación)
* **Objetivo:** Verificar que un mensaje que excede el tope responde `MESSAGE_TOO_LARGE` y cierra la conexión de forma efectiva —drenando la respuesta antes del cierre—, y que el sobre válido encadenado detrás no se procesa ni crea estado.
* **Precondiciones:** Linux o WSL con Bash y Python 3; Hermes compilado; `HOME` temporal aislado; puerto `45859` libre.
* **Entorno y configuración:** `config.json` propio con `puerto: 45859`; `network.json` que autoriza a `PC-B` desde `127.0.0.1` con `submit` habilitado; servidor lanzado por el script.
* **Datos de entrada:** Un único `sendall` con 17 000 bytes `x`, un `\n` y un `submit` válido (`tc053-despues`) terminado en `\n`.
* **Pasos reproducibles:**
  1. Compilar con `make -C src/hermes hermes`.
  2. Ejecutar `bash verif/scripts/TC-053.sh`.
  3. Revisar el código de salida y `verif/results/results_TC-053.md`.
* **Resultado esperado:** La respuesta es `{"error":"MESSAGE_TOO_LARGE","ok":false,"request_id":null,...}` y llega completa antes del cierre. No llega ninguna respuesta para `tc053-despues` y `jobs.json` queda vacío o ausente. El `ping` posterior responde.

#### 2. Fase de Ejecución (Resultados empíricos)
* **Resultado observado:** Ejecución del 2026-11-22 en WSL Ubuntu con código `0`. La respuesta fue `{"error": "MESSAGE_TOO_LARGE", "ok": false, "request_id": null, "version": 1}`; tras el error la conexión cerró sin procesar el sobre encadenado; `jobs.json` quedó con `0` Jobs; el `ping` posterior respondió correctamente.
* **Artefactos de evidencia:** `verif/scripts/TC-053.sh`; `verif/results/results_TC-053.md`.
