# TC-021: Consistencia de transiciones de estado concurrentes

**Requisito cubierto:** RNF-27  
**Nivel de prueba:** Integración / concurrencia

## Objetivo

Verificar que las cancelaciones concurrentes no produzcan estados imposibles ni regresiones, que los estados terminales permanezcan terminales y que el resultado persistido corresponda al estado final.

## Precondiciones

- Linux con Bash, Perl `JSON::PP` y Hermes compilado.
- La prueba usa un `HOME` temporal y no modifica los datos del usuario.
- `/proc` debe estar disponible para detener el scheduler aislado al terminar.

## Ejecución

Desde la raíz del repositorio:

```bash
make -C src/hermes
bash verif/scripts/TC-021.sh
```

El caso crea 10 Jobs `sleep 30` concurrentemente y envía tres solicitudes de cancelación simultáneas por Job. Mientras se procesan, observa los estados persistidos. Comprueba que las transiciones observadas respeten `QUEUED -> RUNNING -> estado terminal` o `QUEUED -> CANCELED`, que ningún estado terminal regrese a otro estado, que todos los Jobs terminen como `CANCELED`, que tengan código de salida no exitoso y tiempo de terminación, y que `jobs.json` siga siendo JSON válido.

Se puede indicar otra cantidad de Jobs:

```bash
bash verif/scripts/TC-021.sh 25
```

Cada ejecución agrega su salida a `verif/results/results_TC-021.md`. El scheduler y los datos temporales se limpian al finalizar.

## Resultado esperado

El script termina con código `0` y muestra:

```text
PASS: 10 Jobs recibieron 30 solicitudes concurrentes; no se observaron regresiones y todos terminaron CANCELED.
```
