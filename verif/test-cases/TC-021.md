# TC-021: Escalamiento de cancelación 

**Requisito cubierto:** RF-30  
**Nivel de prueba:** Integración

#### 1. Fase de Diseño (Planificación)
* **Objetivo:** Verificar que, al cancelar un Job cuyo proceso ignora `SIGTERM`, Hermes espere el periodo de gracia de cinco segundos, aplique terminación forzosa y persista el Job en estado `CANCELED` con código de salida `-9`.
* **Precondiciones:** Sistema Linux con Bash y Hermes compilado. El usuario debe poder crear un directorio temporal y consultar `/proc`. La prueba ejecuta Hermes con un `HOME` temporal aislado para no modificar los Jobs ni la configuración del usuario.
* **Entorno y configuración:** Entorno controlado, compilación con GCC o Clang, scheduler y datos aislados en el `HOME` temporal. Se usa la configuración predeterminada de Hermes; no se requiere LAN ni VPN. `/proc` está disponible para localizar y detener el scheduler de prueba al terminar.
* **Datos de entrada:** Job `bash -c 'trap "" TERM; while :; do sleep 1; done'`, que ignora `SIGTERM` y permanece activo. Se envía una solicitud de cancelación para el `job_id` devuelto por Hermes.
* **Pasos reproducibles:**
  1. Desde la raíz del repositorio, compilar Hermes con `make -C src/hermes`.
  2. Ejecutar `bash verif/scripts/TC-021.sh`.
  3. Revisar el código de salida, la salida de consola y `verif/results/tc021.log`.
* **Resultado esperado:** La cancelación debe devolver código `0` y tardar al menos cinco segundos. La consulta final debe completarse con código `0` y mostrar `Estado: CANCELED` y `Codigo de salida: -9`. El script debe concluir con `[PASS] TC-021` y código de salida `0`.

#### 2. Fase de Ejecución (Resultados empíricos)
* **Resultado observado:** `make -C src/hermes` terminó correctamente sin requerir recompilación. `bash verif/scripts/TC-021.sh` terminó con código `0`; la cancelación tardó 5 segundos y el Job terminó en estado `CANCELED` con código de salida `-9`. Salida final: `[PASS] TC-021`.
