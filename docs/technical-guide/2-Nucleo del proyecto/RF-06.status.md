# RF-06 — Estados QUEUED, RUNNING, SUCCEEDED, FAILED, CANCELED

## Descripción

Hermes maneja un conjunto definido de estados para representar el ciclo de vida de cada Job.

Los estados disponibles son:

* `QUEUED`
* `RUNNING`
* `SUCCEEDED`
* `FAILED`
* `CANCELED`

Cada Job comienza inicialmente en estado `QUEUED`.

A medida que el proceso asociado al Job es ejecutado, Hermes actualiza su estado de acuerdo con el resultado de la ejecución o con una solicitud de cancelación.

El manejo de los estados se encuentra separado del módulo de Jobs mediante los archivos `status.h` y `status.cpp`.

---

## Objetivo

El objetivo de este requerimiento es establecer una representación controlada del estado de cada Job y permitir que Hermes refleje su ciclo de vida durante la ejecución.

Los estados permiten identificar si un Job:

* Está esperando para ejecutarse.
* Se encuentra actualmente en ejecución.
* Terminó correctamente.
* Terminó con errores.
* Fue cancelado.

La implementación de estos estados se integra con la creación y ejecución de procesos, así como con el mecanismo de cancelación de Jobs.

---

La implementación se encuentra organizada de la siguiente manera:

```text
hermes/

├── include/
```

La definición de los estados permanece independiente de la lógica de Jobs y de la implementación de procesos.

El módulo `status` se encarga de representar los estados, mientras que el módulo `job` es responsable de actualizar el estado correspondiente durante el ciclo de vida del Job.

---

## Definición de los estados

Los estados se representan mediante un `enum class`:

```cpp
enum class Status {
    QUEUED,
    RUNNING,
    SUCCEEDED,
    FAILED,
    CANCELED
};
```

### `QUEUED`

Indica que el Job fue creado correctamente y se encuentra pendiente de ejecución.

Es el estado inicial de todos los Jobs.

### `RUNNING`

Indica que el proceso asociado al Job fue iniciado y se encuentra actualmente en ejecución.

Cuando Hermes inicia correctamente el proceso, el estado del Job se actualiza a `RUNNING`.

### `SUCCEEDED`

Indica que el proceso terminó correctamente.

Este estado se establece cuando el proceso hijo termina y devuelve un código de salida que indica una ejecución exitosa.

### `FAILED`

Indica que el proceso terminó con un error.

También se utiliza cuando Hermes no puede ejecutar el programa solicitado, por ejemplo, cuando `execvp()` no consigue iniciar el programa.

El resultado de la ejecución se almacena junto con el estado del Job.

### `CANCELED`

Indica que la ejecución del Job fue cancelada mediante Hermes.

La cancelación se realiza enviando una señal al proceso asociado al Job. Cuando el proceso termina como consecuencia de una cancelación solicitada, Hermes registra el estado `CANCELED`.

---

## Ciclo de vida del Job

Con la implementación actual, el ciclo de vida básico de un Job puede representarse de la siguiente manera:

```text
             crear Job
                 │
                 ▼
              QUEUED
                 │
                 ▼
              RUNNING
             /   |    \
            /    |     \
           ▼     ▼      ▼
     SUCCEEDED  FAILED  CANCELED
```

La transición inicial ocurre cuando el Job es creado:

```text
QUEUED
```

Posteriormente, cuando Hermes inicia el proceso:

```text
QUEUED → RUNNING
```

Cuando el proceso termina correctamente:

```text
RUNNING → SUCCEEDED
```

Cuando el proceso termina con un error:

```text
RUNNING → FAILED
```

Cuando se solicita su cancelación:

```text
RUNNING → CANCELED
```

Estas transiciones son realizadas de acuerdo con el resultado real del proceso y no solamente mediante la asignación manual de un estado.

## Implementación de `status.h`

El archivo `status.h` contiene la definición del tipo `Status` y la función encargada de convertir los estados a texto.

```cpp
#ifndef STATUS_H
#define STATUS_H

#include <string>

using std::string;

enum class Status {
    QUEUED,
    RUNNING,
    SUCCEEDED,
    FAILED,
    CANCELED
};

string statusToString(Status status);

#endif
```

El uso de `enum class` evita utilizar cadenas directamente para representar los estados dentro del programa.

Por ejemplo, en lugar de:

```cpp
job.status = "RUNNING";
```

se utiliza:

```cpp
job.status = Status::RUNNING;
```

Esto permite que el compilador controle que solamente se utilicen estados definidos por Hermes.

---

## Implementación de `status.cpp`

El archivo `status.cpp` contiene la conversión del estado interno a una cadena.

```cpp
#include "status.h"

string statusToString(Status status) {
    switch (status) {
    case Status::QUEUED:
        return "QUEUED";

    case Status::RUNNING:
        return "RUNNING";

    case Status::SUCCEEDED:
        return "SUCCEEDED";

    case Status::FAILED:
        return "FAILED";

    case Status::CANCELED:
        return "CANCELED";
    }

    return "QUEUED";
}
```

Esta conversión permite representar el estado internamente mediante `Status` y almacenarlo o mostrarlo externamente como texto.

Por ejemplo:

```cpp
Status::RUNNING
```

se convierte en:

```text
RUNNING
```

## Integración con `Job`

La estructura `Job` utiliza el tipo `Status` para almacenar su estado actual.

La estructura actual también mantiene información relacionada con el proceso asociado:

```cpp
struct Job {
    unsigned int job_id;
    int pid;
    string programa;
    vector<string> argumentos;
    Status status;
    int codigoSalida;
};
```

El campo `pid` permite asociar el Job con el proceso Linux que Hermes inició.

El campo `codigoSalida` permite almacenar el resultado de la ejecución del proceso.

Para utilizar `Status`, `job.h` incluye:

```cpp
#include "status.h"
```

Debido a la organización del proyecto, los headers se encuentran centralizados en `include/`.

El Makefile utiliza:

```make
CXXFLAGS = -Wall -Wextra -std=c++17 -Iinclude
```

Por lo tanto, los módulos pueden incluir los headers sin utilizar rutas relativas como:

```cpp
#include "../status/status.h"
```

---

## Estado inicial del Job

La función `crearJob()` establece automáticamente el estado inicial:

```cpp
job.status = Status::QUEUED;
```

La función recibe únicamente la información necesaria para crear el Job:

```cpp
Job crearJob(
    const string& programa,
    const vector<string>& argumentos
);
```

El estado no se recibe como parámetro.

Esto evita que un Job recién creado pueda iniciar directamente en un estado incorrecto como:

```text
RUNNING
SUCCEEDED
FAILED
CANCELED
```

Todos los Jobs comienzan en:

```text
QUEUED
```

---

## Actualización del estado durante la ejecución

Una vez creado el Job, Hermes inicia el proceso asociado mediante las funciones del módulo de procesos.

Cuando el proceso comienza correctamente, el estado se actualiza:

```text
QUEUED → RUNNING
```

La actualización se realiza mediante la función encargada de modificar el estado del Job:

```cpp
actualizarEstadoJob(jobId, Status::RUNNING);
```

Una vez que el proceso termina, Hermes obtiene su resultado mediante `waitpid()`.

A partir de este resultado se determina el estado final.

Si el proceso termina correctamente:

```text
RUNNING → SUCCEEDED
```

Si termina con un código de error:

```text
RUNNING → FAILED
```

El resultado también se almacena en el Job.

---

## Manejo del resultado del proceso

Hermes utiliza el resultado obtenido del proceso hijo para determinar su estado final.

La información del resultado se almacena mediante:

```cpp
actualizarResultadoJob(jobId, estado, codigoSalida);
```

De esta manera, el estado del Job no depende únicamente de que el proceso haya sido creado, sino también de cómo terminó su ejecución.

Por ejemplo:

```text
Programa: ls
PID: 12345
Estado: SUCCEEDED
Código de salida: 0
```

Mientras que una ejecución con error puede registrarse como:

```text
Programa: programa_inexistente
PID: 12346
Estado: FAILED
Código de salida: 127
```

## Cancelación de Jobs

Hermes también permite solicitar la cancelación de un Job mediante el comando:

```text
hermes cancel <id>
```

La cancelación se aplica a Jobs que se encuentran en ejecución.

Cuando se solicita la cancelación, Hermes identifica el proceso asociado mediante su `PID` y envía una señal para terminarlo.

El flujo correspondiente es:

```text
RUNNING
   │
   │ hermes cancel <id>
   ▼
CANCELED
```

El proceso que supervisa la ejecución detecta posteriormente la terminación del proceso y actualiza el estado correspondiente.

Esto permite que `CANCELED` represente una terminación provocada por una solicitud explícita de cancelación.

---

## Persistencia del estado

El estado del Job se almacena en:

```text
data/jobs.json
```

junto con el resto de la información del Job.

Por ejemplo:

```json
[
    {
        "job_id": 1,
        "pid": 12345,
        "programa": "sleep",
        "argumentos": [
            "30"
        ],
        "estado": "RUNNING",
        "codigoSalida": 0
    }
]
```

La conversión del estado se realiza mediante:

```cpp
statusToString(job.status)
```

permitiendo convertir:

```cpp
Status::RUNNING
```

en:

```text
RUNNING
```

para posteriormente almacenarlo en JSON.

Cuando el proceso termina, la información persistida se actualiza con el nuevo estado y el código de salida correspondiente.

## Integración con la ejecución de procesos

RF-06 se encuentra actualmente integrado con el módulo encargado de crear y supervisar procesos.

El flujo general es:

```text
hermes job <programa> [argumentos]
             │
             ▼
          crearJob()
             │
             ▼
           QUEUED
             │
             ▼
       iniciar proceso
             │
             ▼
          RUNNING
             │
        ┌────┴────┐
        ▼         ▼
    waitpid()   cancelación
        │         │
        ▼         ▼
  resultado    CANCELED
        │
   ┌────┴────┐
   ▼         ▼
SUCCESS     ERROR
   │         │
   ▼         ▼
SUCCEEDED   FAILED
```

De esta forma, los estados representan el resultado real del ciclo de vida del proceso asociado al Job.

## Cambios realizados

Para implementar RF-06 y su integración con la ejecución de procesos se realizaron los siguientes cambios:

### Nuevo módulo `status`

Se agregaron:

```text
include/status.h
src/status/status.cpp
```

### Cambio en `Job`

Se incorporó el tipo:

```cpp
Status status;
```

para representar el estado actual del Job.

También se incorporaron los datos asociados al proceso:

```cpp
int pid;
int codigoSalida;
```

### Cambio en `crearJob()`

La función dejó de recibir el estado como parámetro y ahora establece automáticamente:

```cpp
job.status = Status::QUEUED;
```

### Actualización durante la ejecución

Se implementó la actualización del estado cuando Hermes inicia y supervisa el proceso:

```text
QUEUED → RUNNING
```

y posteriormente:

```text
RUNNING → SUCCEEDED
RUNNING → FAILED
```

dependiendo del resultado de la ejecución.

### Implementación de cancelación

Se incorporó el comando:

```text
hermes cancel <id>
```

que permite solicitar la terminación de un Job en ejecución y registrar el estado:

```text
CANCELED
```

## Ejemplo de funcionamiento

Al ejecutar:

```text
hermes job sleep 30
```

Hermes crea inicialmente el Job:

```text
Job ID: 1
PID: 12345
Estado: QUEUED
```

Una vez iniciado el proceso:

```text
Job ID: 1
PID: 12345
Estado: RUNNING
```

Si `sleep` termina correctamente:

```text
Job ID: 1
Estado: SUCCEEDED
Código de salida: 0
```

Si el programa no puede ejecutarse:

```text
Job ID: 2
Estado: FAILED
Código de salida: 127
```

Si durante la ejecución se solicita:

```text
hermes cancel 1
```

el Job puede finalizar como:

```text
Job ID: 1
Estado: CANCELED
```

## Alcance actual

Con RF-06 queda implementado:

* Definición de los cinco estados.
* Uso de `enum class Status`.
* Estado inicial `QUEUED`.
* Integración del estado dentro de `Job`.
* Conversión de estados a texto.
* Persistencia del estado en `jobs.json`.
* Separación del módulo de estados respecto al módulo de Jobs.
* Transición de `QUEUED` a `RUNNING`.
* Detección del resultado del proceso mediante `waitpid()`.
* Transición a `SUCCEEDED` o `FAILED`.
* Almacenamiento del código de salida.
* Integración con el mecanismo de cancelación.
* Transición a `CANCELED` cuando un Job en ejecución es cancelado.

### Pendiente para etapas posteriores

Aunque las transiciones básicas ya están implementadas, todavía pueden ampliarse aspectos relacionados con la administración de procesos, entre ellos:

* Manejo de concurrencia entre múltiples Jobs.
* Administración de una cola de ejecución.
* Límite de procesos ejecutándose simultáneamente.
* Manejo de grupos de procesos para cancelar procesos y sus descendientes.
* Recuperación de Jobs en ejecución después de un reinicio.
* Validación más completa de las transiciones de estado.

Estas funcionalidades corresponden a etapas posteriores del desarrollo de Hermes y no forman parte de la implementación básica actual de RF-06.
