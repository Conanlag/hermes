# TC-014: Construcción desde clon limpio

**Requisitos cubiertos:** RNF-01, RNF-02 y RNF-03.
**Requisitos relacionados:** RNF-16 (mínimo privilegio), RF-16 (configuración), RF-18/RF-19 (humo TCP). No sustituye sus casos funcionales completos.
**Métodos de verificación:** Prueba de construcción e integración.
**Nivel de prueba:** Aceptación y reproducibilidad funcional.
**Modo:** local, autocontenido en Linux/WSL. Dos clones temporales del mismo commit y servidor propio en loopback; no requiere PC B.

#### 1. Fase de Diseño (Planificación)

* **Objetivo:** Construir y ejecutar la versión confirmada del proyecto en el Linux declarado, repetir la construcción desde otro clon limpio y demostrar operación, instalación y desinstalación bajo el usuario normal.
* **Precondiciones:** repositorio Git local con HEAD válido; usuario sin privilegios; g++ con C++17, GNU Make y Git instalados según las instrucciones; Python 3, ss, mktemp y tee para el ejecutor de pruebas; /proc y /etc/os-release accesibles; permiso de crear procesos y sockets loopback. No requiere binario previo, acceso a Internet ni instalar paquetes durante la prueba.
* **Entorno y configuración:** dos clones completos A/B con `git clone --no-local --no-checkout` desde el repositorio local, fijados al SHA de HEAD mediante checkout detached. Cada clon tiene HOME y XDG_CONFIG_HOME propios, vacíos. Sus compilaciones se ejecutan en paralelo. Los cambios sin commit del origen no se incluyen ni se borran. La configuración predeterminada actual crea 5 workers cuando se inicia el scheduler; make no lo inicia. Para el humo TCP se habilita un network.json temporal y se elige un puerto libre distinto de 45820.
* **Datos de entrada:** código y cabecera JSON 3.12.0 versionados; comandos make clean, make, make install y make uninstall; --version, --help, health --json, job echo, filter id, job sleep, cancel y red job true.
* **Fuentes:** [ADR-002](../../docs/desicions/ADR-002-Plataforma.md), [entorno de compilación](../../docs/desicions/ADR-003-Entorno.md), [instalación y ejecución](../../docs/technical-guide/1-Requisitos-de-instalacion/Instalacion_y_Ejecucion.md), [dependencias](../../docs/technical-guide/1-Requisitos-de-instalacion/Librerias.md), [mínimo privilegio](../../docs/technical-guide/2-Nucleo%20del%20proyecto/RNF-16-minimo-privilegio-amenazas.md) y [guía de pruebas de red](../scripts/GUIA-PRUEBAS-RED.md).

##### Pasos reproducibles

Desde la raíz, en WSL/Linux, como usuario normal:

```bash
# El script realiza las compilaciones desde cero; no exige compilar el origen.
bash verif/scripts/TC-014.sh
echo $?
```

Puerto fijo opcional, siempre comprobado libre:

```bash
HERMES_TEST_PORT=45868 bash verif/scripts/TC-014.sh
```

HERMES_TEST_CLIENT_ID permite cambiar el ID del cliente temporal, predeterminado PC-B. HERMES_TEST_HOST diferente de localhost/127.0.0.1 produce error de entorno: la medición requiere copias y servidor propios.

* **Resultado esperado:** AC1–AC8 PASS y `PASS: RNF-01 RNF-02 RNF-03 TC-014 sin fallos.`, código **0**. Código **1** para aserción, compilación o limpieza fallida; **2** para error de entorno. Sin omisiones remotas ni código 3.
* **Evidencia:** [results_TC-014.md](../results/results_TC-014.md), secciones acumulativas con commit de origen, árbol, herramientas, distribución, kernel, UID, hashes, humo y códigos. Los logs completos de compilación permanecen temporales durante la ejecución; ante fallo se muestra su tramo final. No se cambia un FAIL histórico por PASS.

##### Alcance y decisiones

El clon se obtiene del repositorio local y se fija a HEAD, no al HEAD cambiante del remoto. `--no-local` usa el transporte Git local sin reutilizar archivos mediante hardlinks. Esto prueba que bastan los archivos versionados para construir, sin copiar binarios, datos ni cambios sin commit del directorio de desarrollo. La descarga de GitHub y la instalación administrativa de las herramientas son precondiciones, no parte de la operación normal sin root.

RNF-02 se interpreta como construcción repetible y comportamiento funcional coincidente con el mismo código, dependencias y toolchain. Se registran hashes SHA256 y si coinciden; no se impone identidad binaria entre arquitecturas o compiladores diferentes. El proyecto incluye src/hermes/include/nlohmann/json.hpp; no se instala una dependencia JSON global ni se descarga durante make.

A diferencia de las pruebas funcionales ordinarias, aquí se ejecuta el objetivo make predeterminado para verificar el procedimiento documentado completo. Ese objetivo inicia el binario sin argumentos, crea configuración/datos/red y adapta los enlaces de desarrollo **dentro de cada clon descartable**. No se ejecuta make en el repositorio de trabajo. Se comparan sus archivos y enlaces versionados de src/ sin seguirlos para confirmar que no cambiaron.

No se invoca sudo ni se modifica PATH, bashrc, instalación real o directorios del sistema. La UID efectiva se verifica para scheduler, Job y servidor. El humo TCP confirma operación local del binario instalado; no acredita LAN/VPN, proxy WSL o firewall. No se intenta ejecutar como root ni cambiar la identidad del usuario.

UID real/efectivo 1000; scheduler, proceso de trabajo y servidor pertenecían al usuario. El humo TCP utilizó 127.0.0.1:39145. Instalación/desinstalación y limpieza satisfactorias; src/ del origen conservado.

* **Estado:** **PASS** para RNF-01, RNF-02 y RNF-03, sin omisiones.

##### Preparación y ejecución previa

Sintaxis Bash/Python, LF, permiso ejecutable y git diff --check verificados. Un primer intento completó compilaciones y humo local/instalación, pero terminó con código 2 porque el aislamiento impidió crear sockets; su evidencia se conserva. Se repitió fuera del aislamiento con autorización, conservando UID 1000, y la ejecución completa terminó con 0. No se requirió instalar dependencias, descargar código desde Internet ni modificar producción. La coincidencia de SHA256 se observó bajo el toolchain registrado; no se extrapola a otros compiladores o arquitecturas.
