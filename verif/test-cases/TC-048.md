# TC-048: Un jobs.json corrupto no expone su contenido en la bitácora

**Requisitos cubiertos:** RNF-15
**Métodos de verificación:** Prueba
**Nivel de prueba:** Robustez y seguridad

#### 1. Fase de Diseño (Planificación)
* **Objetivo:** Verificar que un `jobs.json` irrecuperable detectado al arrancar el scheduler se registra con una causa clasificada, sin contenido del archivo ni texto del parser JSON, y que la consola informa el fallo con un mensaje controlado.
* **Precondiciones:** Linux o WSL con Bash y Python 3; Hermes compilado; `HOME` temporal aislado.
* **Entorno y configuración:** `jobs.json` y `jobs.json.bak` escritos con el mismo JSON truncado y un valor sentinela, de modo que la auto-restauración de RNF-28 no pueda reparar el estado.
* **Datos de entrada:** `{"job_id": 1, "secreto": "rf15secreto12"` en ambos archivos; una invocación de `hermes filter list`.
* **Pasos reproducibles:**
  1. Compilar con `make -C src/hermes hermes`.
  2. Ejecutar `bash verif/scripts/TC-048.sh`.
  3. Revisar el código de salida y `verif/results/results_TC-048.md`.
* **Resultado esperado:** El comando falla con código distinto de cero y un mensaje `No se pudo iniciar el scheduler…`. La bitácora registra `Error interno del daemon` con `detalle: "excepcion de formato JSON (detalle omitido)"`, sin el sentinela ni `[json.`/`parse error`.

#### 2. Fase de Ejecución (Resultados empíricos)
* **Resultado observado:** Ejecución del 2026-11-22 en WSL Ubuntu con código `0`. El arranque se detuvo con `No se pudo iniciar el scheduler: No se pudo recuperar el estado antes de iniciar el scheduler`; el evento registró `detalle: 'excepcion de formato JSON (detalle omitido)'`. El sentinela `rf15secreto12` no apareció ni en la bitácora ni en la consola.
* **Artefactos de evidencia:** `verif/scripts/TC-048.sh`; `verif/results/results_TC-048.md`.
* **Estado:** PASS
