# TC-023: Rechazo explícito cuando la cola está llena

**Requisitos cubiertos:** RF-23, RF-25
**Nivel de prueba:** Integración / concurrencia

## Objetivo

Verificar que `trabajos_maximos` limita los Jobs activos admitidos, que las solicitudes concurrentes excedentes se rechazan con un mensaje explícito y no crean registros, que cada rechazo se registra en `events.jsonl` con el límite y el motivo, y que un Job terminal libera capacidad.

## Precondiciones

- Linux con Bash, Perl `JSON::PP` y Hermes compilado.
- La prueba usa un `HOME` temporal y no modifica los datos del usuario.

## Ejecución

Desde la raíz del repositorio:

```bash
make -C src/hermes
bash verif/scripts/TC-023.sh
```

El caso configura `trabajos_maximos: 2`, acepta un Job semilla y lanza ocho solicitudes simultáneas. Debe aceptarse solo una solicitud adicional; las siete restantes deben recibir el mensaje de cola llena. Comprueba que los rechazos no se persistan y que cada uno genere un evento `WARN` con `job_id: null`, `motivo_del_rechazo`, trabajos activos y capacidad. También verifica que una repetición con el mismo `request_id` reutilice el Job existente aun con la capacidad llena, y que una cancelación libere un espacio para una nueva solicitud.

## Resultado esperado

El script termina con código `0` y muestra:

```text
PASS: el límite concurrente rechazó sin persistir Jobs extra, registró los rechazos y liberó la capacidad.
```
