# TC-052: Cierre ordenado frente a mensaje truncado

**Requisitos cubiertos:** RNF-24
**Métodos de verificación:** Prueba
**Nivel de prueba:** Funcional y robustez

#### 1. Fase de Diseño (Planificación)
* **Objetivo:** Verificar que el servidor distingue el fin de flujo con el búfer sincronizado —cierre normal y silencioso— del fin de flujo con bytes sin delimitador, que conserva `INCOMPLETE_MESSAGE` y se documenta como `SIN_EFECTO`.
* **Precondiciones:** Linux o WSL con Bash y Python 3; Hermes compilado; `HOME` temporal aislado; puerto `45858` libre.
* **Entorno y configuración:** `config.json` propio con `puerto: 45858`; `network.json` que autoriza a `PC-B` desde `127.0.0.1`; servidor lanzado por el script.
* **Datos de entrada:** (a) `ping` completo, respuesta leída y `shutdown(SHUT_WR)`; (b) un objeto JSON sin cerrar (`tc052-truncado`) seguido de `shutdown(SHUT_WR)`.
* **Pasos reproducibles:**
  1. Compilar con `make -C src/hermes hermes`.
  2. Ejecutar `bash verif/scripts/TC-052.sh`.
  3. Revisar el código de salida, `verif/results/results_TC-052.md` y `events.jsonl`.
* **Resultado esperado:** El caso (a) no recibe datos tras el FIN y no deja registros anómalos. El caso (b) recibe `INCOMPLETE_MESSAGE` y produce un único registro `Solicitud interrumpida` con `motivo: FIN_SIN_MENSAJE`, `resultado: SIN_EFECTO` y `bytes_recibidos` positivo.

#### 2. Fase de Ejecución (Resultados empíricos)
* **Resultado observado:** Ejecución del 2026-11-22 en WSL Ubuntu con código `0`. El cierre ordenado terminó en EOF sin datos adicionales y sin registros; el truncado recibió `{"error":"INCOMPLETE_MESSAGE","ok":false,"request_id":null,"version":1}` y dejó un registro con `bytes_recibidos: 66`, `motivo: FIN_SIN_MENSAJE` y `resultado: SIN_EFECTO`.
* **Artefactos de evidencia:** `verif/scripts/TC-052.sh`; `verif/results/results_TC-052.md`.
