# TC-047: Los errores de network.json no exponen valores de configuración

**Requisitos cubiertos:** RNF-15
**Métodos de verificación:** Prueba
**Nivel de prueba:** Robustez y seguridad

#### 1. Fase de Diseño (Planificación)
* **Objetivo:** Verificar que cada error de `network.json` cita la clave o la regla incumplida, nunca el valor de configuración ni fragmentos crudos del archivo, y que la bitácora no recibe esos valores.
* **Precondiciones:** Linux o WSL con Bash; Hermes compilado; `HOME` temporal aislado; sin servidor escuchando en el puerto configurado.
* **Entorno y configuración:** `config.json` válido en `127.0.0.1:$PUERTO`; `network.json` reescrito cuatro veces, una por escenario.
* **Datos de entrada:** Cuatro `network.json`: (a) clave `tls` presente con valor sentinela; (b) cliente con `sha256` en lugar de `id`/`direcciones`; (c) `ambito_trabajos` con un espacio; (d) JSON truncado con sentinela en `id`.
* **Pasos reproducibles:**
  1. Compilar con `make -C src/hermes hermes`.
  2. Ejecutar `bash verif/scripts/TC-047.sh`.
  3. Revisar el código de salida y `verif/results/results_TC-047.md`.
* **Resultado esperado:** Los cuatro arranques fallan con código distinto de cero; cada mensaje cita la clave o la regla (`tls`, `sha256`, `Ámbito de trabajos inválido`, `network.json no es un JSON válido`) y no contiene el sentinela ni texto del parser JSON. La bitácora no contiene ninguno de los cuatro sentinelas.

#### 2. Fase de Ejecución (Resultados empíricos)
* **Resultado observado:** Ejecución del 2026-11-20 en WSL Ubuntu con código `0`. Los cuatro diagnósticos fueron: `Quite tls de network.json y registre clientes por id y direcciones IPv4`, `Los clientes ahora requieren id y direcciones IPv4, no sha256`, `Ámbito de trabajos inválido` y `network.json no es un JSON válido`. Ningún sentinela (`rf15secreto8` a `rf15secreto11`) apareció en la salida ni en `events.jsonl`.
* **Artefactos de evidencia:** `verif/scripts/TC-047.sh`; `verif/results/results_TC-047.md`.
