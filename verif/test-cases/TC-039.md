# TC-039: Rechazo determinista de formatos inválidos en el servidor

**Requisitos cubiertos:** RNF-14, RNF-32
**Métodos de verificación:** Prueba
**Nivel de prueba:** Funcional y robustez

#### 1. Fase de Diseño (Planificación)
* **Objetivo:** Verificar que el servidor responde con un código de error propio y determinista ante cada formato inválido, y que documenta cada rechazo una sola vez según la ventana de 60 s por código.
* **Precondiciones:** Linux o WSL con Bash y Python 3; Hermes compilado; `HOME` temporal aislado; puerto `45850` libre.
* **Entorno y configuración:** `config.json` propio de la prueba con `puerto: 45850`; `network.json` que autoriza a `PC-B` desde `127.0.0.1`; servidor lanzado por el script.
* **Datos de entrada:** Once mensajes inválidos, cada uno con su defecto aislado: JSON roto, byte nulo embebido, UTF-8 inválido (`0xFF`), anidamiento de 40 niveles, clave desconocida en el nivel superior, `operation` de 40 bytes, `params` no vacío en `ping`, 16392 bytes con delimitador, `request_id` con espacio, operación desconocida y `version: 2`. Después, un segundo byte nulo idéntico para ejercitar la ventana.
* **Pasos reproducibles:**
  1. Compilar con `make -C src/hermes hermes`.
  2. Ejecutar `bash verif/scripts/TC-039.sh`.
  3. Revisar el código de salida y `verif/results/results_TC-039.md`.
* **Resultado esperado:** Cada defecto recibe el código que le corresponde (`INVALID_JSON`, `NUL_BYTE`, `INVALID_UTF8`, `TOO_DEEP`, `INVALID_REQUEST`, `INVALID_OPERATION`, `INVALID_PARAMS`, `MESSAGE_TOO_LARGE`, `INVALID_REQUEST_ID`, `UNKNOWN_OPERATION`, `UNSUPPORTED_VERSION`). Se registra exactamente un evento `Mensaje rechazado` por código —el segundo byte nulo no añade otro— y ninguno aparece duplicado como `Solicitud interrumpida`. El `ping` posterior responde correctamente.

#### 2. Fase de Ejecución (Resultados empíricos)
* **Resultado observado:** Ejecución del 2026-11-19 en WSL Ubuntu con código `0`. Los diez formatos recibieron su código propio, incluida la repetición del byte nulo. Se contaron `10` eventos `Mensaje rechazado` para `10` códigos distintos, cada uno con `ip`, `identidad`, `motivo` y `bytes_recibidos` mayor que cero, y ningún evento `Solicitud interrumpida`. El `ping` posterior respondió `ok: true`.
* **Artefactos de evidencia:** `verif/scripts/TC-039.sh`; `verif/results/results_TC-039.md`.
