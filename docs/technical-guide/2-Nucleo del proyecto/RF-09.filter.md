# RF-09 — Listado de trabajos y filtros por estado, ID y programa

## Descripción

El requisito funcional RF-09 permite consultar los trabajos almacenados en `data/jobs.json` mediante diferentes filtros.

Los filtros disponibles son:

* `id`: busca un trabajo específico mediante su identificador.
* `status`: busca todos los trabajos que tengan un estado determinado.
* `programa`: busca todos los trabajos asociados a un programa específico.

La funcionalidad se implementa mediante un módulo independiente llamado `filter`, evitando colocar la lógica de consulta directamente en `main.cpp`.

---

## Objetivo

Proporcionar un mecanismo para consultar los trabajos registrados en Hermes utilizando diferentes propiedades de un Job.

La sintaxis general es:

```bash
hermes filter <tipo_filtro> <valor>
```

Ejemplos:

```bash
hermes filter id 2
hermes filter status QUEUED
hermes filter programa ls
```

## Archivo `filter.h`

El archivo `filter.h` declara las funciones disponibles para realizar las consultas:

```cpp
#ifndef FILTER_H
#define FILTER_H

#include <string>

using std::string;

void filtrarPorId(unsigned int job_id);

void filtrarPorStatus(const string& status);

void filtrarPorPrograma(const string& programa);

#endif
```

### Funciones

#### `filtrarPorId`

```cpp
void filtrarPorId(unsigned int job_id);
```

Recibe un identificador de tipo `unsigned int` y busca el Job correspondiente mediante el campo:

```json
"job_id"
```

Ejemplo:

```bash
hermes filter id 2
```

---

#### `filtrarPorStatus`

```cpp
void filtrarPorStatus(const string& status);
```

Recibe un estado y busca todos los Jobs que tengan ese valor en el campo:

```json
"status"
```

Ejemplo:

```bash
hermes filter status QUEUED
```

Los estados definidos actualmente en Hermes son:

```text
QUEUED
RUNNING
SUCCEEDED
FAILED
CANCELED
```

---

#### `filtrarPorPrograma`

```cpp
void filtrarPorPrograma(const string& programa);
```

Recibe el nombre del programa y busca todos los Jobs cuyo campo `programa` coincida con el valor proporcionado.

Ejemplo:

```bash
hermes filter programa ls
```

---

## Filtro por programa

La función `filtrarPorPrograma()` consulta el archivo `data/jobs.json` y compara el valor proporcionado con el campo `programa` de cada Job.

La condición principal es:

```cpp
if (job.contains("programa") &&
    job["programa"].is_string() &&
    job["programa"] == programa)
```

Antes de realizar la comparación se comprueba que:

1. El Job contenga el campo `programa`.
2. El valor almacenado sea una cadena.
3. El valor sea igual al programa solicitado.

Esto permite evitar accesos incorrectos a propiedades que no existan en el objeto JSON.

## Información mostrada

Cuando se encuentra un Job, el filtro muestra:

```text
Job ID: 1
Programa: ls
Estado: QUEUED
Argumentos: -la
------------------------
```

La información se obtiene directamente del objeto JSON:

```json
{
    "job_id": 1,
    "programa": "ls",
    "argumentos": [
        "-la"
    ],
    "status": "QUEUED"
}
```

El campo utilizado para mostrar el estado es:

```cpp
job["status"]
```

No se utiliza `estado`, ya que el nombre definido para la propiedad es `status`.

## Lectura de `jobs.json`

Los tres filtros utilizan el archivo:

```text
data/jobs.json
```

El archivo se abre mediante:

```cpp
ifstream archivoLectura(archivoJobs);
```

Posteriormente se verifica que pueda abrirse:

```cpp
if (!archivoLectura.is_open()) {
    cout << "No se pudo abrir " << archivoJobs << endl;
    return;
}
```

Una vez abierto, su contenido se carga utilizando `nlohmann::json`:

```cpp
archivoLectura >> jobs;
```

La lectura está protegida mediante un bloque `try/catch` para detectar errores de sintaxis JSON:

```cpp
try {
    archivoLectura >> jobs;
} catch (const json::parse_error&) {
    cout << "Error al leer " << archivoJobs << endl;
    archivoLectura.close();
    return;
}
```

---

## Búsqueda de Jobs

Una vez cargado el archivo, se recorren los elementos del arreglo:

```cpp
for (const auto& job : jobs) {
    ...
}
```

Para el filtro por programa se realiza una comparación directa:

```cpp
job["programa"] == programa
```

Si existe una coincidencia, se muestran los datos del Job.

El filtro no se detiene después de encontrar una coincidencia, por lo que puede mostrar múltiples Jobs que utilicen el mismo programa.

---

## Manejo de argumentos

Los argumentos se almacenan en el campo:

```json
"argumentos"
```

Como este campo es un arreglo JSON, se verifica antes de recorrerlo:

```cpp
if (job.contains("argumentos") &&
    job["argumentos"].is_array()) {
```

Posteriormente se muestran todos sus elementos:

```cpp
for (const auto& argumento : job["argumentos"]) {
    cout << argumento << " ";
}
```

Por ejemplo, para:

```json
{
    "programa": "ls",
    "argumentos": [
        "-la",
        "/home"
    ]
}
```

se obtiene:

```text
Argumentos: -la /home
```

---

## Manejo cuando no existen coincidencias

La variable:

```cpp
bool encontrado = false;
```

permite determinar si al menos un Job coincidió con el filtro.

Cuando se encuentra un Job:

```cpp
encontrado = true;
```

Si después de recorrer todo el archivo no se encontró ninguna coincidencia, se muestra un mensaje:

```text
No se encontraron Jobs con el programa indicado: ls
```

Para el filtro por ID se utiliza un mensaje equivalente indicando que no se encontró el Job solicitado.

## Integración con `main.cpp`

El comando `filter` se procesa desde `main.cpp`.

La primera validación comprueba que se hayan proporcionado los argumentos necesarios:

```cpp
if (argc < 4) {
    cout << "Uso: hermes filter <id|status|programa> <valor>" << endl;
    return 1;
}
```

Posteriormente se obtiene el tipo de filtro:

```cpp
string tipoFiltro = argv[2];
```

Hermes determina qué función ejecutar mediante una serie de condiciones:

```cpp
if (tipoFiltro == "id") {

    unsigned int id = std::stoul(argv[3]);

    filtrarPorId(id);

} else if (tipoFiltro == "status") {

    filtrarPorStatus(argv[3]);

} else if (tipoFiltro == "programa") {

    filtrarPorPrograma(argv[3]);

} else {

    cout << "Filtro no reconocido: "
         << tipoFiltro << endl;

    cout << "Filtros disponibles: id, status, programa" << endl;

    return 1;
}
```

De esta forma, `main.cpp` solamente determina qué filtro debe ejecutarse. La lectura y búsqueda dentro de `jobs.json` permanece dentro de `filter.cpp`.

## Ejemplo de `jobs.json`

Un archivo con varios Jobs puede tener la siguiente estructura:

```json
[
    {
        "job_id": 1,
        "programa": "ls",
        "argumentos": [
            "-la"
        ],
        "status": "QUEUED"
    },
    {
        "job_id": 2,
        "programa": "hola",
        "argumentos": [],
        "status": "QUEUED"
    },
    {
        "job_id": 3,
        "programa": "ls",
        "argumentos": [
            "/home"
        ],
        "status": "RUNNING"
    }
]
```

Al ejecutar:

```bash
hermes filter programa ls
```

se mostrarían los Jobs 1 y 3.
