# RF-23 — Rechazo y registro de solicitudes que excedan límites

## Objetivo

Hermes rechaza las solicitudes nuevas que exceden la capacidad configurada de trabajos activos y registra cada rechazo en `events.jsonl`.

## Comportamiento

- `trabajos_maximos` define la capacidad de admisión. Se cuentan los Jobs en `QUEUED` y `RUNNING`; los estados terminales no consumen capacidad.
- La comprobación de capacidad ocurre dentro de la modificación protegida de `jobs.json`, por lo que solicitudes concurrentes no pueden exceder el límite ni crear Jobs adicionales.
- Una solicitud excedente recibe un mensaje explícito y un código de salida distinto de cero.
- Hermes escribe un evento de nivel `WARN` con `job_id: null`, porque el rechazo ocurre antes de crear un Job. El contexto incluye el programa, `motivo_del_rechazo`, `trabajos_activos`, `capacidad` y `request_id` cuando se proporcionó.
- Si no se puede escribir el evento, Hermes informa el fallo de registro además de rechazar la solicitud; no convierte el rechazo en una aceptación.
- Un reintento idempotente válido reutiliza el Job existente y no se rechaza por capacidad.

## Verificación

El caso de integración [TC-023](../../../verif/test-cases/TC-023.md) verifica los rechazos concurrentes, la ausencia de registros de Job adicionales, y que cada rechazo produzca un evento con el motivo y los valores del límite.

```bash
make -C src/hermes
bash verif/scripts/TC-023.sh
```
