# RF-17 — Ayuda de uso y códigos de salida

## Descripción

El requisito RF-17 dota a Hermes de ayuda integrada: el comando `--help` describe uso, comandos, estados, ejemplos y códigos de salida sin necesidad de documentación externa. Es presentación pura del lado cliente local (alcance Fase 1): no lee disco, no toca procesos y no puede fallar por estado del sistema.

La ayuda vive en su propio módulo `help`, espejo de `version`: un contrato mínimo (`int mostrarAyuda()`) con el texto centralizado fuera de `main.cpp`. El despachador solo la invoca y propaga su código de salida. La lista blanca del validador (RF-02) la reconoce como comando autorizado, por lo que participa del mismo régimen de mensajes útiles y códigos que el resto.

---

## Objetivo

La meta técnica exacta es ofrecer descubrimiento autónomo del CLI con códigos de salida adecuados: `0` para ayuda, versión y operaciones exitosas; `1` para cualquier rechazo o fallo.

> El cliente deberá ofrecer ayuda de uso y códigos de salida adecuados para éxito y error.

Consideraciones actuales:
- Hace: `--help` imprime uso, 7 comandos, 5 estados, 4 ejemplos y tabla `0 éxito / 1 error`, siempre con código `0`.
- Hace: comandos inválidos rechazados con lista actualizada (ya incluye `--help`) y código `1`.
- Hace: `hermes` sin argumentos y `--version` conservan su comportamiento y código `0`.
- NO hace: ayuda por comando (`hermes job --help`) ni paginación; es un único documento.
- NO hace: ayuda remota o versionada por red (Fase 1: cliente local).

```text

├── include/
│   ├── help.h
│   ├── version.h
│   └── validator.h
├── src/
│   ├── main.cpp
│   ├── help/
│   │   └── help.cpp
│   ├── version/
│   │   └── version.cpp
│   └── validator/
│       └── validator.cpp
└── Makefile
```

| Archivo / directorio | Responsabilidad |
| -------------------- | --------------- |
| `include/help.h` | Contrato: `int mostrarAyuda()` |
| `src/help/help.cpp` | Texto de ayuda por `cout`, retorno `0` |
| `src/main.cpp` | Rama `--help` junto a `--version` con `return` directo |
| `src/validator/validator.cpp` | Lista blanca ampliada con `--help` (3 puntos) |
| `Makefile` | Descubre `help.cpp` vía `find`, sin edición |

## Definición de los estados

Este RF no crea estados de negocio. Usa los códigos de salida del proceso como su único vocabulario:

| Código | Significado |
| ------ | ----------- |
| `0` | Éxito: ayuda mostrada, versión mostrada, operación aceptada. |
| `1` | Error: comando inválido, validación rechazada, operación fallida. |

`mostrarAyuda()` siempre devuelve `0`; `main` lo propaga con `return`.

## Implementación de `.h`

**1. Propósito.** `help.h` declara la presentación de ayuda sin exponer su texto. Permite a `main.cpp` incluirla con `#include "help.h"` vía `-Iinclude`.

**2. Dependencias.** Ninguna (ni siquiera `<string>`): no recibe ni devuelve texto, solo un `int`.

**3. Estructuras.** Ninguna.

**4. Prototipos.**

```cpp
int mostrarAyuda();
```

Se eligió la firma espejo de `version()` (`int`, sin parámetros) para que el despachador la trate igual y el código viaje por `return` sin variables intermedias.

---

## Implementación de `.cpp`

`src/help/help.cpp` solo usa `<iostream>` y escribe el documento por `cout` en un orden fijo: cabecera, uso, comandos (uno por línea con su descripción), estados, ejemplos ejecutables y códigos. Termina con `return 0`.

```cpp
int mostrarAyuda() {
    cout << "HERMES - Gestor de trabajos en cola" << endl;
    // ... uso, comandos, estados, ejemplos, códigos ...
    return 0;
}
```

Se usó `cout` plano en vez de `info()` (azul) porque un documento de 20 líneas con color cansa y rompe el copiar-pegar en algunas terminales. No lleva `try/catch`: no hay archivos ni parseo que proteger, solo consola. No lee `jobs.json` ni consulta módulos: si el disco está roto, la ayuda sigue funcionando.

---

## Integración con `main.cpp` y `validator`

`main.cpp` coloca la rama junto a `--version`, antes de cualquier comando con argumentos, con salida inmediata:

```cpp
if (comando == "--version") {
    return version();
}

if (comando == "--help") {
    return mostrarAyuda();
}
```

`validator.cpp` se actualizó en sus 3 puntos (mensaje de vacío, condición, mensaje de no autorizado) porque su comentario `IMPORTANTE` exige registrar cada comando nuevo; sin eso, `--help` moriría como no reconocido antes de mostrarse.

## Integración con RF-01, RF-02 y RF-10

Documenta sin modificar: describe `job` (RF-01), `filter`, `cancel` (RF-10) y los estados (RF-06) tal como existen. Reutiliza el régimen de RF-02 (lista blanca y códigos) en vez de crear uno propio.

## Ejemplo de funcionamiento

```bash
./hermes --help; echo $?
```

```text
HERMES - Gestor de trabajos en cola

Uso: hermes <comando> [argumentos..]

Comandos:
  job <programa> [argumentos..]  Crea un trabajo y devuelve su ID
  filter id <numero>             Muestra un trabajo por su ID
  filter status <ESTADO>         Lista trabajos por estado
  filter programa <nombre>       Lista trabajos por programa
  cancel <id>                    Cancela un trabajo en cola o en ejecucion
  --version                      Muestra la version
  --help                         Muestra esta ayuda

Estados: QUEUED, RUNNING, SUCCEEDED, FAILED, CANCELED

Ejemplos:
  hermes job sleep 30
  hermes filter id 1
  hermes filter status RUNNING
  hermes cancel 1

Codigos de salida: 0 exito, 1 error
0
```

```bash
./hermes foo; echo $?
```

```text
Comando no reconocido: foo. Comandos validos: job, filter, cancel, --version, --help
1
```

Sin efectos en disco en ambos casos.
