# RF-06 — Estados QUEUED, RUNNING, SUCCEEDED, FAILED, CANCELED

## Descripción

Hermes debe manejar un conjunto definido de estados para representar el ciclo de vida de cada Job.

Los estados disponibles son:

* `QUEUED`
* `RUNNING`
* `SUCCEEDED`
* `FAILED`
* `CANCELED`

Cada Job debe comenzar inicialmente en estado `QUEUED`.

El manejo de los estados se separa del módulo de Jobs mediante el archivo `status.h` y su implementación `status.cpp`.

---

## Objetivo

El objetivo de este requerimiento es establecer una representación controlada del estado de cada Job.

Esto permite que Hermes pueda identificar si un Job:

* Está esperando para ejecutarse.
* Se encuentra actualmente en ejecución.
* Terminó correctamente.
* Terminó con errores.
* Fue cancelado.

La definición de los estados también proporciona la base para implementar posteriormente la ejecución de procesos, concurrencia y cancelación.

---

## Estructura del módulo

La implementación se encuentra organizada de la siguiente manera:

```text
hermes/
├── include/
│   ├── job.h
│   └── status.h
│
└── src/
    ├── job/
    │   └── job.cpp
    │
    └── status/
        └── status.cpp
```

La separación permite mantener la definición del estado independiente de la lógica de creación y almacenamiento de los Jobs.


## Definición de los estados

Los estados se representan mediante un `enum class`:

```cpp
enum class Status {
    QUEUED,
    RUNNING,
    SUCCEEDED,
    FAILED,
    CANCELED
};
```

### `QUEUED`

Indica que el Job fue creado correctamente pero todavía no ha comenzado su ejecución.

Es el estado inicial de todos los Jobs.

### `RUNNING`

Indica que el proceso asociado al Job se encuentra actualmente en ejecución.

### `SUCCEEDED`

Indica que el proceso terminó correctamente.

### `FAILED`

Indica que la ejecución del proceso terminó con un error.

### `CANCELED`

Indica que el Job fue cancelado antes de completar su ejecución.

## Implementación de `status.h`

El archivo `status.h` contiene la definición del tipo `Status` y la función encargada de convertir los estados a texto.

```cpp
#ifndef STATUS_H
#define STATUS_H

#include <string>

using std::string;

enum class Status {
    QUEUED,
    RUNNING,
    SUCCEEDED,
    FAILED,
    CANCELED
};

string statusToString(Status status);

#endif
```

El uso de `enum class` evita utilizar cadenas directamente para representar los estados dentro del programa.

Por ejemplo, en lugar de:

```cpp
job.status = "RUNNING";
```

se utiliza:

```cpp
job.status = Status::RUNNING;
```

Esto permite que el compilador controle que solamente se utilicen estados definidos por Hermes.

---

## Implementación de `status.cpp`

El archivo `status.cpp` contiene la conversión del estado interno a una cadena.

```cpp
#include "status.h"

string statusToString(Status status) {

    switch (status) {

        case Status::QUEUED:
            return "QUEUED";

        case Status::RUNNING:
            return "RUNNING";

        case Status::SUCCEEDED:
            return "SUCCEEDED";

        case Status::FAILED:
            return "FAILED";

        case Status::CANCELED:
            return "CANCELED";
    }

    return "QUEUED";
}
```

Esta conversión es necesaria principalmente para almacenar el estado en el archivo JSON de los Jobs.

---

## Integración con `Job`

La estructura `Job` utiliza el tipo `Status` para almacenar su estado actual.

```cpp
struct Job {
    unsigned int job_id;
    string programa;
    vector<string> argumentos;
    Status status;
};
```

Para utilizar `Status`, `job.h` incluye el header correspondiente:

```cpp
#include "status.h"
```

Debido a la organización del proyecto, los headers se encuentran centralizados en `include/`.

El Makefile utiliza:

```make
CXXFLAGS = -Wall -Wextra -std=c++17 -Iinclude
```

Por lo tanto, los módulos pueden incluir los headers sin tener que utilizar rutas relativas como:

```cpp
#include "../status/status.h"
```

## 8. Estado inicial del Job

La función `crearJob()` establece automáticamente el estado inicial:

```cpp
job.status = Status::QUEUED;
```

La función solamente recibe la información necesaria para crear el Job:

```cpp
Job crearJob(
    const string& programa,
    const vector<string>& argumentos
);
```

El estado no se recibe como parámetro.

Esto evita que un Job recién creado pueda iniciar directamente en un estado incorrecto como:

```text
RUNNING
SUCCEEDED
FAILED
CANCELED
```

Todos los Jobs comienzan en:

```text
QUEUED
```

## Persistencia del estado

El estado del Job se almacena en `data/jobs.json` junto con el resto de la información del Job.

Ejemplo:

```json
[
    {
        "job_id": 1,
        "programa": "ls",
        "argumentos": [
            "-la"
        ],
        "estado": "QUEUED"
    }
]
```

La conversión se realiza mediante:

```cpp
statusToString(job.status)
```

permitiendo convertir:

```cpp
Status::QUEUED
```

en:

```text
QUEUED
```

para posteriormente almacenarlo en JSON.

## Cambios realizados

Para implementar RF-06 se realizaron los siguientes cambios:

### Nuevo módulo `status`

Se agregaron:

```text
include/status.h
src/status/status.cpp
```

### Cambio en `Job`

Se sustituyó la representación del estado mediante `string` por:

```cpp
Status status;
```

### Cambio en `crearJob()`

La función dejó de recibir el estado como parámetro y ahora establece automáticamente:

```cpp
job.status = Status::QUEUED;
```

## Ejemplo de funcionamiento

Al crear un Job:

```text
hermes job create ls -la
```

se genera un Job con:

```text
Job ID: 1
Programa: ls
Argumentos: -la
Estado: QUEUED
```

Y se almacena:

```json
[
    {
        "job_id": 1,
        "programa": "ls",
        "argumentos": [
            "-la"
        ],
        "estado": "QUEUED"
    }
]
```

En esta etapa Hermes únicamente establece el estado inicial. La transición hacia `RUNNING`, `SUCCEEDED`, `FAILED` o `CANCELED` dependerá de la implementación posterior de ejecución y control de procesos.
