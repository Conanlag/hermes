### TC-001: Enviar trabajo válido
**Requisitos cubiertos:** RF-01, RF-02
**Nivel de prueba:** Sistema

#### 1. Fase de Diseño (Planificación)
* **Objetivo:** Validar que Hermes acepta el envío de un programa con argumentos, genera un identificador único de trabajo, lo persiste en estado QUEUED y rechaza las variantes inválidas (vacías, mal formadas, no autorizadas) con mensaje útil y código de salida 1.
* **Precondiciones:** Repositorio clonado limpio; `src/hermes` compilado con `make clean && make` sin errores; `data/jobs.json` respaldado; terminal WSL con permisos de ejecución sobre `./hermes`.
* **Entorno y configuración:** Linux (WSL), compilador GCC (g++, `-Wall -Wextra -std=c++17 -Iinclude`), entorno controlado, clon limpio, límite de concurrencia definido en config.json.
* **Datos de entrada:** `./hermes job echo hola` (válido); `./hermes job ""` (vacía); `./hermes cancel 999999` y `./hermes filter id abc` (no autorizada / mal formada de control); inspección de `data/jobs.json`.
* **Pasos reproducibles:**
  1. Compilar: `cd src/hermes && make clean && make`.
  2. Enviar trabajo válido: `./hermes job echo hola` y anotar el `job ID` impreso (ej. `N`).
  3. Verificar persistencia: `./hermes filter id N` y comprobar `Programa: echo`, `Estado: QUEUED` (o posterior), `Argumentos: hola`.
  4. Verificar unicidad: repetir el paso 2 y comprobar que el nuevo ID es `N+1` (no reutilizado).
  5. Entrada vacía: `./hermes job ""` y comprobar rechazo con mensaje útil y código `1` (`echo $?`).
  6. Entrada mal formada: `./hermes filter id abc` y comprobar mensaje `ID mal formado` y código `1`.
  7. Entrada no autorizada: `./hermes foo` y comprobar mensaje con comandos válidos y código `1`.
* **Resultado esperado:** Paso 2 imprime `job ID: N` con código `0`; paso 3 muestra el trabajo persistido con sus metadatos; paso 4 genera ID estrictamente mayor; pasos 5–7 rechazan con mensaje útil en `stderr`, código `1` y sin modificar `data/jobs.json`.
