# TC-013: Configuración y salud

**Requisitos cubiertos:** RF-16 y RF-24.
**Requisitos relacionados:** RNF-11/RNF-28 (persistencia y recuperación), RNF-12/RNF-13/RNF-26 (escucha segura), RNF-15 (redacción), RNF-16 (usuario sin privilegios). Este caso no sustituye sus pruebas específicas.
**Métodos de verificación:** Prueba de integración y comprobación de API real.
**Nivel de prueba:** Funcional y robustez.
**Modo:** local, autocontenido en Linux/WSL de PC A; no necesita PC B.

#### 1. Fase de Diseño (Planificación)

* **Objetivo:** Comprobar la configuración de rutas, capacidad y escucha, y la fidelidad del resumen administrativo de salud ante servicios activos, inactivos y fuentes dañadas o inaccesibles.
* **Precondiciones:** usuario sin privilegios; Hermes compilado; Bash, Python 3, g++, cabeceras de nlohmann/json, ss, mktemp y tee; /proc accesible y sockets IPv4 loopback permitidos.
* **Entorno y configuración:** HOME y XDG_CONFIG_HOME temporales por escenario. Concurrencia 1 y cola 1 en la integración; servidor real en loopback, clientes y permisos propios. Puerto dinámico libre o HERMES_TEST_PORT validado; nunca se utiliza 45820 para escuchar. El valor predeterminado 45820 se verifica únicamente mediante lectura, sin abrirlo. El auxiliar C++ se compila en el temporal enlazando config.cpp, config_update.cpp, event_log.cpp y access.cpp reales.
* **Datos de entrada:** configuración ausente, heredada, personalizada y corrupta; puertos límite y tipos inválidos; trabajos sleep 120 locales y remotos; registros antiguos de servicio; eventos ERROR/INFO y líneas JSONL incompletas; archivos sin permisos de lectura.
* **Fuentes:** [guía de pruebas de red](../scripts/GUIA-PRUEBAS-RED.md), [RF-16](../../docs/technical-guide/2-Nucleo%20del%20proyecto/RF-16.configuracion-de-interfaz.md), [RF-24](../../docs/technical-guide/2-Nucleo%20del%20proyecto/RF-24.resumen-salud.md), contexto actual de red y guía WSL PC A/PC B.

##### Pasos reproducibles

Desde la raíz, en WSL de PC A:

```bash
make -C src/hermes hermes
bash verif/scripts/TC-013.sh
echo $?
```

Puerto opcional:

```bash
HERMES_TEST_PORT=45866 bash verif/scripts/TC-013.sh
```

El puerto solicitado se verifica libre para el arranque principal; los reinicios que prueban un cambio de puerto utilizan otro puerto libre dinámico. HERMES_TEST_CLIENT_ID permite cambiar el ID del cliente registrado (predeterminado PC-B). Un HERMES_TEST_HOST distinto de localhost/127.0.0.1 se rechaza como error de entorno, sin contactar servidores externos.

* **Resultado esperado:** PASS Vn/ACn para los doce criterios y `PASS: RF-16 RF-24 TC-013 sin fallos.`. Código 0 para PASS, 1 para aserción/limpieza fallida, 2 para error de entorno. No existen omisiones remotas requeridas ni código 3 en este caso local.
* **Evidencia:** [results_TC-013.md](../results/results_TC-013.md), con sección acumulativa por ejecución, fecha, kernel, commit, estado del árbol, puertos y resultados. Los fallos previos se conservan.

##### Alcance y decisiones

El rango 1024–65535 se confirmó experimentalmente y se corrigió en RF-16 y en el contexto técnico antes de definir las aserciones. El test no intenta enlazar puertos privilegiados ni valida disponibilidad de todos los puertos del rango.

Se usa el objetivo `make -C src/hermes hermes`, que solo compila. Ninguna invocación del test arranca el binario sin argumentos ni cambia los enlaces data/config/network del repositorio. Tampoco cambia src/, el HOME operativo, portproxy o firewall. Las señales se dirigen exclusivamente a procesos propios y a schedulers identificados por el descriptor del scheduler.lock temporal.

Las fuentes de salud son independientes: se espera activamente un estado estable para comparar conteos. Se permite la reparación desde respaldo documentada; la consulta no reconcilia estados RUNNING antiguos. Un resultado completo con servicios inactivos o errores históricos devuelve 0.

Hermes Red activo indica registro y bloqueo del servidor local. No demuestra conectividad LAN, proxy Windows, firewall o VPN. En WSL NAT el proxy puede cambiar el origen observado; no se deduce la IP de PC B ni se reutilizan direcciones históricas. La demostración entre equipos corresponde a TC-010.

##### Ajuste de alcance solicitado

La entrada extrema UINT64_MAX para concurrencia/cola se retiró del criterio obligatorio por indicación del usuario. AC4 valida los rangos configurables 1–64 y 0–256, sus límites y valores adyacentes; también exige aceptar `configmax 64 --cola 256` y rechazar 65/257 sin modificar el archivo. Los resultados anteriores se conservan como historial y no se consideran resultados de esta versión. [INC-002](../../docs/incidents/INC-002-config-enteros-grandes.md) queda como observación exploratoria fuera del alcance, sin afirmar que se haya corregido producción. El uso de enteros grandes para el campo puerto sigue verificando su fallback documentado.
