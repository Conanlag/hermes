# TC-038: La ventana de 60 s no silencia solicitudes ya procesadas

**Requisitos cubiertos:** RF-28
**Métodos de verificación:** Prueba
**Nivel de prueba:** Funcional y robustez

#### 1. Fase de Diseño (Planificación)
* **Objetivo:** Verificar que la ventana de 60 s amortigua solo el ruido previo al protocolo: N solicitudes procesadas cuya respuesta se pierde dejan N registros, no uno.
* **Precondiciones:** Linux o WSL con Bash y Python 3; Hermes compilado; `HOME` temporal aislado; puerto `45833` libre.
* **Entorno y configuración:** `config.json` propio de la prueba con `puerto: 45833`; `network.json` que autoriza a `PC-B` desde `127.0.0.1`; servidor lanzado por el script.
* **Datos de entrada:** Veinte operaciones `ping` completas con `request_id` correlativo, cada una seguida de un `RST` inmediato (`SO_LINGER` con plazo 0) que destruye la respuesta.
* **Pasos reproducibles:**
  1. Compilar con `make -C src/hermes hermes`.
  2. Ejecutar `bash verif/scripts/TC-038.sh`.
  3. Revisar el código de salida y `verif/results/results_TC-038.md`.
* **Resultado esperado:** Se registran exactamente veinte eventos `Solicitud interrumpida`, todos con `resultado: ACEPTADA`, `operacion: ping` y el `request_id` de su conexión; ninguna solicitud aparece como `Cliente desconectado`; el servicio responde un `ping` posterior. Es el contraste directo con TC-033, donde cinco conexiones sin datos producen un solo aviso.

#### 2. Fase de Ejecución (Resultados empíricos)
* **Resultado observado:** Ejecución del 2026-11-19 en WSL Ubuntu con código `0`, repetida cuatro veces con el mismo desenlace. En cada corrida se registraron `20 de 20` eventos `Solicitud interrumpida` con `resultado: ACEPTADA`, `motivo: ERROR_SOCKET`, `operacion: ping` y `bytes_recibidos: 76`; no hubo entradas `Cliente desconectado` y el `ping` posterior respondió correctamente.
* **Artefactos de evidencia:** `verif/scripts/TC-038.sh`; `verif/results/results_TC-038.md`.
