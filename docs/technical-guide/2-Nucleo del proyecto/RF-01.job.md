# RF-01 — Gestión y ejecución de Jobs

## Objetivo

Hermes debe aceptar un programa junto con sus argumentos y crear un Job asociado, asignándole un identificador único.

La implementación actual permite:

* Recibir un programa y sus argumentos.
* Crear un Job.
* Asignar un `job_id` único.
* Crear un proceso real de Linux.
* Ejecutar el programa solicitado.
* Asociar el PID del proceso con el Job.
* Persistir la información del Job en `data/jobs.json`.
* Devolver el identificador del Job y el PID del proceso.
* Permitir que Hermes continúe disponible mientras el proceso ejecutado continúa funcionando.

El funcionamiento se divide entre los módulos `job` y `process`, evitando concentrar toda la lógica de administración de procesos dentro de `job.cpp`.

# Dependencia nlohmann/json

Hermes utiliza `nlohmann/json` para almacenar los Jobs en formato JSON.

La biblioteca se encuentra directamente dentro del proyecto:

```text
include/nlohmann/json.hpp
```

La versión utilizada es:

```text
nlohmann/json v3.12.0
```

Es una biblioteca *header-only*, por lo que no es necesario enlazar una biblioteca adicional.

El Makefile utiliza:

```make
CXXFLAGS = -Wall -Wextra -std=c++17 -Iinclude
```

Por lo tanto, los archivos pueden incluirla mediante:

```cpp
#include <nlohmann/json.hpp>

using json = nlohmann::json;
```

No es necesario utilizar:

```text
-ljson
```

# Estructura `Job`

El Job actualmente contiene:

```cpp
struct Job {

    unsigned int job_id;

    int pid;

    string programa;

    vector<string> argumentos;

    Status status;

    int codigoSalida;

};
```

## `job_id`

Identificador único asignado por Hermes.

Ejemplo:

```text
job_id: 7
```

El identificador se obtiene revisando los Jobs almacenados en:

```text
data/jobs.json
```

y tomando el siguiente valor disponible después del ID máximo encontrado.

---

## `pid`

Identificador del proceso creado por Linux.

Por ejemplo:

```text
Job ID: 7
PID: 5053
```

El `job_id` identifica el trabajo dentro de Hermes, mientras que el `pid` identifica el proceso dentro del sistema operativo.

---

## `programa`

Nombre o comando que Hermes debe ejecutar.

Ejemplo:

```text
sleep
```

---

## `argumentos`

Argumentos enviados al programa.

Por ejemplo:

```bash
hermes job sleep 120
```

produce:

```text
programa = "sleep"

argumentos:
    "120"
```

---

## `status`

Representa el estado actual del Job.

Los estados disponibles son:

```text
QUEUED
RUNNING
SUCCEEDED
FAILED
CANCELED
```

La definición completa se encuentra documentada en RF-06.

---

## `codigoSalida`

Almacena el código de salida obtenido cuando el proceso termina.

Por ejemplo:

```text
codigoSalida: 0
```

indica una terminación normal del programa.

---

# Función `crearJob()`

La creación de Jobs se realiza mediante:

```cpp
Job crearJob(
    const string& programa,
    const vector<string>& argumentos
);
```

La función recibe:

1. El nombre del programa.
2. Los argumentos correspondientes.

A partir de estos datos se crea el Job y se inicia el proceso asociado.

El Job resultante contiene:

```text
job_id
pid
programa
argumentos
status
codigoSalida
```

---

# Generación del `job_id`

Hermes utiliza `data/jobs.json` como fuente para determinar el siguiente identificador.

Inicialmente:

```text
siguienteId = 1
```

Después se recorren los Jobs existentes.

Por ejemplo, si existen:

```text
1
2
3
```

el siguiente Job utilizará:

```text
4
```

La implementación busca el ID máximo, por lo que tampoco depende únicamente de la cantidad de elementos del arreglo.

Si existen:

```text
1
5
```

el siguiente ID será:

```text
6
```

# Creación del proceso

La creación del proceso se encuentra encapsulada en el módulo `process`.

La operación principal utiliza:

```cpp
fork();
```

El resultado permite distinguir entre:

```text
pid < 0 → error

pid == 0 → proceso hijo

pid > 0 → proceso padre
```

La separación de esta responsabilidad permite que `job.cpp` trabaje con Jobs mientras `process.cpp` administra los procesos de Linux.

---

# Proceso hijo

Cuando `fork()` devuelve:

```text
0
```

el código se encuentra ejecutándose dentro del proceso hijo.

El hijo prepara los argumentos del programa y utiliza:

```cpp
execvp()
```

para reemplazar su imagen por el programa solicitado.

Por ejemplo:

```bash
hermes job sleep 120
```

produce conceptualmente:

```text
Hermes
   │
   └── fork()
        │
        └── proceso hijo
             │
             └── execvp()
                  │
                  └── sleep 120
```

---

# Proceso padre

El proceso padre recibe el PID del proceso hijo:

```cpp
pid_t pid = fork();
```

Cuando:

```text
pid > 0
```

ese valor corresponde al proceso creado.

Hermes almacena dicho PID en el Job:

```text
job.pid = pid;
```

Por ejemplo:

```text
Job ID: 7
PID: 5053
Programa: sleep
```

---

# Ejecución del proceso

Una vez creado el proceso, Hermes puede devolver el resultado de creación al usuario sin bloquear la terminal esperando directamente dentro del comando `job`.

Por ejemplo:

```bash
hermes job sleep 120
```

puede producir:

```text
job ID: 7
PID: 5053
```

Mientras:

```text
sleep 120
```

continúa ejecutándose como proceso independiente.

---

# Supervisión del proceso

La supervisión del proceso se encuentra implementada en el módulo `process`.

Para esperar la terminación de un proceso se utiliza:

```cpp
waitpid()
```

La función de supervisión obtiene el resultado de ejecución y permite determinar si el proceso:

```text
terminó correctamente
```

o:

```text
terminó con error
```

Este resultado posteriormente se utiliza para actualizar el estado del Job.

---

# Ejecución mediante `execvp()`

`execvp()` permite ejecutar programas disponibles mediante el `PATH` del usuario.

Por ejemplo:

```bash
hermes job ls -la
```

ejecuta conceptualmente:

```text
ls -la
```

De la misma forma:

```bash
hermes job ping -c 5 127.0.0.1
```

ejecuta:

```text
ping -c 5 127.0.0.1
```

Los argumentos recibidos por Hermes son conservados y enviados al proceso hijo.

---

# Persistencia

Los Jobs son almacenados en:

```text
data/jobs.json
```

Ejemplo:

```json
[
    {
        "job_id": 7,
        "pid": 5053,
        "programa": "sleep",
        "argumentos": [
            "120"
        ],
        "status": "RUNNING",
        "codigoSalida": 0
    }
]
```

La información permanece almacenada aunque el proceso principal de Hermes termine.

---

# Lectura de `jobs.json`

Antes de generar un nuevo ID, Hermes intenta abrir:

```text
data/jobs.json
```

Si el archivo existe, se carga mediante `nlohmann/json`.

Si no existe información válida, se utiliza un arreglo vacío:

```cpp
json::array()
```

Esto permite que Hermes comience a crear Jobs desde un archivo vacío.

---

# Relación entre Job y proceso

La relación puede representarse como:

```text
Hermes
  │
  └── Job 7
       │
       ├── programa: sleep
       ├── argumentos: 120
       ├── status: RUNNING
       └── PID: 5053
                    │
                    ▼
                 Linux
                    │
                    └── sleep 120
```

El `job_id` pertenece a Hermes.

El `PID` pertenece al sistema operativo.

# Pruebas realizadas

## Prueba 1 — `sleep`

```bash
hermes job sleep 120
```

Resultado:

```text
job ID: 7
PID: 5053
```

El proceso puede verificarse mediante:

```bash
ps -fp 5053
```

---

## Prueba 2 — `echo`

```bash
hermes job echo hola
```

El programa imprime:

```text
hola
```

Debido a que `echo` termina inmediatamente, su proceso puede desaparecer antes de realizar una consulta mediante `ps`.

Esto corresponde al comportamiento normal del programa.

---

## Prueba 3 — `ping`

```bash
hermes job ping -c 5 127.0.0.1
```

Hermes crea el proceso y `ping` recibe sus argumentos correctamente.

Esta prueba permite comprobar la ejecución de programas con múltiples argumentos.

---

## Prueba 4 — Programa inexistente

Si se ejecuta:

```bash
hermes job hola
```

y `hola` no existe como programa ejecutable, `execvp()` no puede iniciar el programa.

El proceso informa el error correspondiente mediante `stderr` y Hermes registra el resultado de la ejecución como un Job fallido.

---

# Ejecución sin `sudo`

La creación de procesos no requiere privilegios de administrador.

Los procesos son creados utilizando los permisos del usuario que ejecuta Hermes.

Por lo tanto, una ejecución normal utiliza:

```bash
hermes job sleep 120
```

y no requiere:

```bash
sudo hermes job sleep 120
```
