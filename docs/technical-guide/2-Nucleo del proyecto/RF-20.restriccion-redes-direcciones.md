# RF-20: Restricción a redes y direcciones permitidas

## Objetivo

Aplicar las reglas configuradas a la dirección IPv4 de origen obtenida de
`accept4()`, antes de responder o procesar operaciones. Una conexión no
autorizada se cierra sin respuesta; el servicio sigue atendiendo conexiones
posteriores.

## Configuración

La clave opcional `redes_permitidas` de `config.json` contiene IP individuales o
rangos IPv4 CIDR. Una IP sin prefijo equivale a `/32`. Sin esta clave, solo se
permite `127.0.0.0/8`. La lista configurada reemplaza completamente ese valor:
para conservar acceso local, incluirlo explícitamente. Una lista vacía deniega
todos los orígenes.

Ejemplo para un servidor cuya IP LAN sea `192.168.1.20`:

```json
{
    "interfaz": "192.168.1.20",
    "puerto": 45820,
    "redes_permitidas": [
        "127.0.0.0/8",
        "192.168.1.0/24"
    ]
}
```

Integrar estas claves en la configuración existente conservando el directorio,
la concurrencia y la cola. Reemplazar las direcciones del ejemplo por las reales.
Reiniciar `hermes red start` para aplicar los cambios. `interfaz` controla dónde
se escucha; `redes_permitidas` controla qué orígenes pueden acceder. Configurar
`0.0.0.0` no autoriza por sí mismo a ningún cliente remoto.

Para permitir solo un equipo, usar por ejemplo `192.168.1.25` en lugar del rango.
Para una VPN, agregar exclusivamente las IP o subredes asignadas a sus clientes,
por ejemplo `10.8.0.0/24` o `100.100.10.20/32`. Hermes no detecta automáticamente
si una dirección privada pertenece a una LAN o una VPN: el administrador define
los rangos autorizados y la validación utiliza el origen observado por TCP,
incluido cualquier NAT intermedio.

## Validación y persistencia

Las reglas deben pertenecer a los espacios definidos en
[RNF-13: Acceso remoto limitado a LAN/VPN](RNF-13.acceso-remoto-LAN-VPN.md).
Las IP individuales equivalen a `/32`; los bits de host de una regla CIDR se
normalizan. Por ejemplo, `192.168.1.25/24` representa `192.168.1.0/24`.

Si existe `redes_permitidas` pero es inválida, el servidor falla antes de abrir
el puerto. No conserva parcialmente entradas válidas ni vuelve a una lista más
permisiva. La API `actualizarConfiguracion()` permite modificar la lista mediante
`CambiosConfiguracion::redesPermitidas` y `valorRedesPermitidas`; valida todas las
reglas antes de guardar atómicamente y conserva las demás claves.
