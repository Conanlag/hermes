# TC-046: Un config.json corrupto no expone su contenido

**Requisitos cubiertos:** RNF-15
**Métodos de verificación:** Prueba
**Nivel de prueba:** Robustez y seguridad

#### 1. Fase de Diseño (Planificación)
* **Objetivo:** Verificar que el fallo de parseo de `config.json` se documenta con una causa controlada —sin contenido del archivo ni texto del parser— tanto en la bitácora como en el mensaje de error de actualización.
* **Precondiciones:** Linux o WSL con Bash y Python 3; Hermes compilado; `HOME` temporal aislado.
* **Entorno y configuración:** `config.json` con la llave de cierre ausente y un valor sentinela: `{"trabajos_maximos": 3, "comentario": "rf15secreto7"`.
* **Datos de entrada:** Una invocación de `hermes red job 127.0.0.1 true` (carga la configuración) y una de `hermes configmax 6` (actualiza la configuración).
* **Pasos reproducibles:**
  1. Compilar con `make -C src/hermes hermes`.
  2. Ejecutar `bash verif/scripts/TC-046.sh`.
  3. Revisar el código de salida y `verif/results/results_TC-046.md`.
* **Resultado esperado:** La bitácora contiene una advertencia `Error al parsear config.json…` con `detalle: "JSON mal formado"` y la ruta del archivo, sin el sentinela ni `[json.`. `configmax` falla con `No se pudo interpretar config.json: JSON mal formado`, sin contenido del archivo.

#### 2. Fase de Ejecución (Resultados empíricos)
* **Resultado observado:** Ejecución del 2026-11-20 en WSL Ubuntu con código `0`. El evento registró `{"archivo": ".../config.json", "detalle": "JSON mal formado", "trabajos_maximos": 5}` y `configmax` respondió `No se pudo actualizar la configuración: No se pudo interpretar config.json: JSON mal formado`. El sentinela no apareció en la bitácora ni en la salida de error.
* **Artefactos de evidencia:** `verif/scripts/TC-046.sh`; `verif/results/results_TC-046.md`.
